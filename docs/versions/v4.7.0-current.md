## 设计要点

### T1: 元素选中能力

**实现方案**: 原型 HTML 在 iframe 中渲染，通过 postMessage 协议实现：
- iframe 内注入 inspector.js 脚本
- hover 高亮（outline）+ click 选中（蓝色边框）
- 选中后 postMessage 上报：`{type: 'element_selected', selector: 'div.card > h2', tagName: 'h2', text: '...', styles: {...}}`
- 父组件接收后显示属性面板 / 注入到对话上下文

### T2: 元素→对话交互

选中元素后，对话输入框自动注入上下文提示：
- `[已选中: <h2 class="title">标题文本</h2>]`
- 用户可直接输入修改意图："把这个标题改大一点，颜色改成蓝色"
- prompt 中注入选中元素的 HTML + CSS 上下文

### T3: AI 局部修改

- AI 返回修改后的 HTML 片段
- 前端通过 postMessage 通知 iframe 替换对应元素
- 支持 undo（保留修改前快照）

### T4: 项目级部署

**当前**: 每个需求的原型独立生成，通过 prototype_bundle 临时聚合预览
**改为**: 项目有一个持久化的原型站点目录
- 路径: `{project.local_path}/.arc/prototype/`
- 每次原型交付物更新时，增量合并到站点目录
- 支持本地 dev server 预览（vite preview）或推送到 S3/Vercel

**需求维度（T5）**: 
- 仅做 iframe sandbox 预览（当前能力保留）
- 新增自然语言微调入口（选择元素 + 对话修改）
- 不再承担"部署"职责

## 约束

- iframe 内脚本注入需考虑 CSP 策略
- 元素选中不能干扰原型本身的交互（click 事件需区分 inspect 模式 vs 正常浏览）
- 项目级站点目录不纳入 git（.gitignore 排除 `.arc/prototype/`）
- S3 部署为可选能力，默认只做本地预览
