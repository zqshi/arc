## 版本目标

为 BINARY_APP 构建产物（v6.0 构建、v6.1 签名）加上分发层：商店上传（App Store Connect / Play Console / Tauri updater）+ 制品分发层（下载页 / 更新元数据）。凭证可配置、非阻塞——未配凭证 skip 商店上传，产物落制品仓可手动下载。这是"不同项目类型落地"终局第四步：构建 → 签名 → **分发**。

## 版本验证标准

1. 商店上传器抽象 + App Store Connect / Play Console / Tauri updater 实现
2. 二进制制品分发层（下载页 / 更新元数据生成）
3. 未配凭证 → skip 商店上传，产物落制品仓可手动下载
4. 配了凭证 → 签名后产物（v6.1）经商店上传成功

## 版本范围

- 商店上传器抽象（Distributor 接口，复用 v6.1 Signer 注册点模式）

## 各任务实施要点

### T1 — Distributor 抽象
- `Distributor` domain 接口: `async upload(artifact_path, signed, credentials) -> DistributeResult`
- 复用 v6.1 SigningCredentials 加密存储模式（分发凭证也项目维度加密）
- `get_distributor(platform)` 注册表（同构 get_signer）

### T2-T4 — 商店上传器
- App Store Connect: altool/xcrun 或 App Store Connect API
- Play Console: Google Play Developer API（service account JSON，即 v6.1 的 play_key_json）
- Tauri updater: 上传到更新服务器 + 生成 latest.json 元数据
- graceful skip: 凭证未配 → skip

### T5 — 制品分发层
- 生成下载页（产物列表 + 签名状态）
- 生成更新元数据（Tauri updater latest.json / Sparkle appcast）
- 未签名产物标记 "unsigned" 警告

## 对后续版本的约束

- 分发凭证复用 v6.1 加密基础设施，禁止明文存 DB
- 商店上传器走 get_distributor 注册表，graceful skip 不阻断
- v6.3 项目治理规范传递假设分发层完成
- play_key_json（v6.1 定义为分发凭证）在本版本消费
