## 各任务实施要点

### T1-T4 — prompt-upgrade P2
- 复用 `execution/llm_review.py` 的公共审查接口 (#8-10 已提取, drift/error_loop/tool_loop 共用)
- 每处判断: 先评估"结构校验能否做 🟡 预筛" → 能则混合判断 (预筛+LLM), 不能则纯 LLM
- 降级兜底: LLM 异常/超时时回退到原规则判断或放行, 不阻断主流程
- 同 PR 必须含单元测试 (mock LLM 返回, 验证判断/降级/边界)

### T5 — ruff 债务清理
- `ruff check --fix` 自动修 47 fixable (F401 未使用 import + I001 排序)
- E501 行太长 (69 处) 手动折行, 优先本次新增文件
- 不改逻辑, 纯格式/清理; 修后跑全量 pytest 确认无回归

### T6 — 前端类型债务清理
- 16 未使用变量/import (TS6133/TS6196): 直接删, 零风险
- 18 真实类型 (TS2322/2339/2352/2345): 逐个分析
  - ArtifactEditor/RollbackButton: API client 缺 todos/projects 属性 → 补类型
  - ApprovalDialog/ExperienceList: ReactNode → 修正类型
  - useProjectDetail/SettingsPage: 类型转换 → 明确类型
  - UnifiedWorkspaceView: 多类型 → 收窄联合类型
- 每修一类跑 `npx tsc -b --noEmit` 确认 (提交前必跑, 见 feedback_frontend_tsc_before_commit)

## 对后续版本的约束

- prompt-upgrade 14/14 完成后, 新增 execution 层判断禁止再用规则执行式 (正则/字面匹配/硬编码), 必须走 LLM 或混合判断
- CI 必须保持绿色 (backend-lint + frontend-check), 新增代码不得引入新 ruff/tsc error
- 前端新增组件/改 import 后提交前必跑 tsc -b --noEmit (不能只靠 Vite dev 按需编译)
