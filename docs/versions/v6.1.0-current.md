## 版本目标

为 BINARY_APP 构建产物加上签名/公证层（v6.0 波次1 已打通 tauri linux bundle 构建）。凭证可配置、非阻塞——未配凭证 graceful skip（warning 不阻断构建），配了走签名流程。这是"不同项目类型落地"终局的第三步：构建 → **签名** → 分发。

## 版本验证标准

1. 签名器抽象（Signer 接口）+ Apple/Windows/Android 三平台签名器实现
2. 凭证配置项同步 `.env.example`，未配 → graceful skip（构建不阻断，仅 warning）
3. 配了凭证 → BINARY_APP 构建产物经签名 + (Apple) notarize 通过
4. v6.0 波次2/3 镜像若与本版本并行推进，签名链路对 web/apk 产物同样适用

## 各任务实施要点

### T1 — Signer 抽象 + 凭证 Settings
- `Signer` domain 接口: `async sign(artifact_path, credentials) -> SignResult`
- `SignResult`: signed_path / signature_id / skipped(bool, graceful skip) / error
- 凭证 Settings: `apple_dev_id` / `apple_team_id` / `win_ev_cert_path` / `win_ev_password` / `play_key_json`（全 optional，空=skip）
- **复用 v5.9.0/v6.0 注册点模式**: `get_signer(build_target)` 注册表，禁止 service 写 if 分支

### T2-T4 — 平台签名器
- Apple: codesign + xcrun notarytool（macOS 原生工具，需 mac runner 或容器内 xcode）
- Windows: signtool（需 EV 证书文件）
- Android: apksigner（JDK + keystore）
- **graceful skip 原则**: 任一凭证未配 → 该平台签名 skipped=True，构建不阻断

### T5 — graceful skip 路由
- DeployService 部署前按 build_target 选 signer，signer.skipped=True 时仅 warning 日志，继续上传未签名产物
- 与 v6.0 BinaryArtifactDeployer 协作：签名在部署前，产物签名后落 artifacts/

## 对后续版本的约束

- 凭证配置项必须同步 `.env.example`（配置一致性 6.3）
- 签名器一律走 get_signer 注册表，禁止 service 写 if build_target 分支
- 未配凭证必须 graceful skip，不阻断构建（非阻塞原则）
- v6.2 分发层假设产物已签名（签名在 v6.1 完成）
