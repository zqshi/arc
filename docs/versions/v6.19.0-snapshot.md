# v6.19.0 Snapshot — 原生客户端平台扩展（Windows → iOS → 鸿蒙）

> 状态: 已归档 (2026-06-30)
> 起始 commit: b7337b0 (激活) / 收尾 62a7966 (续13补)
> 上一版本: [v6.18.0](v6.18.0-snapshot.md)

## 版本目标

让 BINARY_APP 项目能构建并签名分发 Windows / iOS / 鸿蒙 原生客户端产物, 对齐已存在的三平台签名器链路 (v6.1 APPLE/WINDOWS/ANDROID), 消除"签名器齐了但构建目标没跟上"的断链。不破坏现有 linux/web/android-apk 三目标, 不改 DDD 领域行为。

核心约束: 容器化沙箱无法构建三新平台产物 (Windows 需 WebView2 / iOS 需 Xcode / 鸿蒙需 DevEco), 走 CI 编排 (GHA matrix job 产产物 + arc 编排签名分发)。

## 关键技术决策

| 决策 | 理由 |
|------|------|
| 新平台构建走 CI 编排 (方案A), 不扩 `SandboxRuntime` ABC | `SandboxRuntime` 契约是同步单命令 `run_command→str`, GHA 是分钟级异步 batch + 文件产物, 契约错配; arc 核心是编排+签名+分发非实时构建 |
| 先 artifact 显式建模再接构建 runtime (铁律) | 延续 v6.1/v6.9, 跳层会被劝退 (见 feedback_artifact_before_runtime) |
| 新增 BuildTarget 同步 12+1 处注册点 | 禁止只改枚举, `execution_backend.TARGET_BACKENDS` 登记为第 13 处真相源, 未登记抛 ValueError |
| 就绪检测真实探活 + 缓存后台刷新 | 只判凭证非空是虚假, GHA `verify_token` + S3 `head_bucket` 真验有效性; 乐观策略 `verified=None` 判 ready 避免误灰显 |
| 延续 v6.1 mock 验证签名链路模式 | 端到端 blocked 于凭证时, 命令构造+链路用 mock 验证, 真实接入 runner 直接用 |

## 遗留问题

- **M2 三平台构建端到端 (硬阻断, 用户凭证)**: `ARC_GHA_TOKEN` (PAT actions:write) + 云端 `ARC_STORAGE_*` (须云端 S3 非本地 MinIO, presigned host 须公网可达) → 验 Windows `dispatch_build→poll→download→BUILD artifact`。iOS 需 macOS runner + Apple 账号; 鸿蒙需 self-hosted runner (label=harmony, 预装 DevEco)。
- **签名分发端到端 (T4/T7/T10 独立 blocked)**: Windows EV 证书 / Apple Developer + provisioning / 华为 .p12+.cer+.p7b。
- **OpenHands/Codex 真注入**: blocked 于 runtime 环境, 集成测试 `test_db_declarations_override_env` env 依赖失败 (deselect)。
- **真实 Agent LLM 端到端**: BaaS provision 走真实 Agent 对话到 ARCHITECTURE 产出 tech_architecture 未在运行态验过 (graceful skip 风险)。
- **前端 9 组件超 300 拆分 (P2)**: 续11 记入 backlog; SAWarning 循环依赖 (agent_sessions/conversations 等互 FK) 既有架构特征非漂移。
- **生产 DB nullable alter 风险**: `review_feedbacks.model_version`/`status` z21 含 backfill, 部署前确认无 NULL。
