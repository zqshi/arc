## 版本目标

为 v6.0 打通的 BINARY_APP 构建产物加上签名/公证层（Apple codesign+notarytool / Windows signtool / Android apksigner）。凭证可配置、非阻塞——用户为自己创建的项目配签名凭证，未配 graceful skip。这是"不同项目类型落地"终局第三步：构建 → **签名** → 分发。

## 关键决策

- **凭证项目维度加密存储（非全局 config）**: 初版 T1 误把凭证做成全局 config，用户澄清纠正——Arc 是应用构建平台，凭证是用户为自己项目配的。修正为项目维度 + Fernet 加密（签名凭证高敏感，不能明文存 DB）。按平台分字段 enc_apple/win/android_creds
- **domain 通过回调注入加解密**: Project.set/get_signing_creds 接收 encrypt/decrypt 回调，application 层注入 infrastructure/crypto 函数，避免 domain→infrastructure 违规（DDD 合规）
- **签名路由按产物平台（非 build_target）**: _detect_sign_targets 扫 .app/.exe/.apk 后缀选 signer。tauri linux 的 deb/AppImage 无标准签名机制 → 不签（原 build_target 硬编码映射 APPLE 语义错误，已修正）
- **graceful skip 三态**: SignResult.signed/skip/fail。凭证未配 → skip 不阻断；签名失败 → fail 记 error 但产物仍上传（分发层 v6.2 决定是否接受未签名产物）
- **cryptography 显式声明**: crypto.py 直接 import，从 python-jose transitive 改为 pyproject 直接依赖（避免 jose 升级风险）

## 约束

- 签名凭证项目维度加密存储（Fernet），禁止明文存 DB
- domain 通过回调注入加解密，禁止 domain→infrastructure 违规
- 签名路由按产物平台（.app/.exe/.apk），禁止 build_target 硬编码映射
- 签名器一律走 get_signer 注册表，graceful skip 不阻断构建
- v6.2 分发层假设产物已签名（签名在 v6.1 完成）；未签名产物分发层决定是否接受
