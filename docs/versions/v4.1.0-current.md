# v4.1.0 — 智能闭环补全

> **主题**: 让"越迭代越聪明"从口号变为代码现实
> **目标**: 补全经验反哺 → 规划 的断裂链路，激活经验质量飞轮

---

## 版本目标

1. 规划阶段注入历史经验 + 领域模型 → 规划不再从零开始
2. 经验反馈闭环闭合 → reuse_count / confidence 随实际复用动态更新
3. 领域模型参与规划决策 → 从"文档知识"升级为"决策智能"

## 各任务详细设计

### T1: 规划 Prompt 注入经验上下文

**改动点**: `planning_service.py` → `generate_roadmap()`

在 `PLANNING_SYSTEM_PROMPT.format()` 前，查询与本次规划相关的历史经验：
- 从 ExperienceRepository 按 project_id 获取估算类+范围变更类经验
- 用 MemoryScorer 打分取 Top-5
- 注入 prompt 的 constraints 区域

**预期效果**: 规划时 AI 能看到"上次版本规划了12项只完成了8项"这种校准信息。

---

### T2: 规划 Prompt 注入领域模型

**改动点**: `planning_service.py` → `_collect_features()` 或 `generate_roadmap()`

在 PLANNING_SYSTEM_PROMPT 中新增 {domain_model_context} 占位符：
- 从 project.domain_model 提取 subdomains + aggregates + relations
- 格式化为"当前架构现实"section
- 让 AI 规划时理解：新增功能涉及哪些聚合、是否需要新增聚合

**预期效果**: 规划给出的 complexity 估算有架构依据而非凭空猜测。

---

### T3: 经验复用反馈闭环

**改动点**: 
- `prompt_builder.py` → `_build_experience_context()` 记录本次注入了哪些经验 ID
- `execution_engine.py` / `conversation/service.py` → AI 回复完成后，检测注入的经验是否被"使用"
- 触发条件: 如果 AI 回复中引用/呼应了注入经验的 solution，则更新该经验

**更新逻辑**:
```python
experience.record_reuse()  # reuse_count += 1, last_reused_at = now
if outcome == "success":
    experience.boost_confidence(0.05)  # max 1.0
```

**预期效果**: MemoryScorer 的 recency + frequency 维度激活，高频复用的经验自然排序靠前。

---

### T4: 规划注入历史估算偏差

**改动点**: `planning_service.py` → 新增 `_collect_estimation_history()`

从 ExperienceRepository 查询 category=ESTIMATION 且 project_id 匹配的经验，提取：
- 历史版本计划 vs 实际完成率
- 复杂度 S/M/L 的实际耗时均值

注入 PLANNING_SYSTEM_PROMPT 的 constraints 区域。

**预期效果**: 第三个版本开始，规划给出的时间估算自动校准，不再系统性低估。

---

### T5: 领域模型冲突检测

**改动点**: 新增 `application/planning/conflict_detector.py`

输入: 待规划的 features list + project.domain_model
输出: 冲突警告 list (哪些 feature 修改同一聚合、跨聚合通信是否新增)

用 LLM 做推理，不硬编码规则。

**预期效果**: 版本规划阶段就能预警"功能A和功能B都修改订单聚合，建议排序而非并行"。

---

### T6: 跨项目经验共享

**改动点**:
- Experience entity 新增 scope=GLOBAL 支持
- ExperienceService 新增 `promote_to_global()` 方法
- prompt_builder → _build_experience_context 同时检索 GLOBAL scope 经验
- 前端：经验详情页新增"提升为全局经验"操作

**触发条件**: 经验 reuse_count >= 3 且 confidence >= 0.85 时，提示用户提升

**预期效果**: 用户做了10个React项目，第11个项目创建时，自动继承"React项目性能优化先查重渲染"这类全局经验。

---

### T7: 扫描增量 diff 感知

**改动点**: `scan_task.py` → `_persist_result()` + 新增 `_compute_scan_diff()`

- 存储上次扫描结果的 hash 或结构化摘要
- 新一次扫描完成后，对比新旧 domain_model diff
- 生成"本次变更摘要"(新增了哪些聚合、删除了哪些实体)
- diff 结果附加到 project 的变更记录

**预期效果**: 用户 push 代码后重新扫描，能看到"本次扫描检测到新增了 Payment 聚合"而非只看到完整替换后的结果。

---

### T8: User 实体贫血修复

**改动点**: `domain/user/entity.py`

添加行为方法：
- `change_password()` / `verify_password()`
- `update_profile()`
- `deactivate()` / `reactivate()`
- `has_permission()`

**预期效果**: 修复质量检测发现的领域模型腐烂信号。

---

## 验收标准

1. 创建第2个版本时，规划 prompt 中能看到第1个版本的估算偏差数据
2. 同一条经验被注入3次后，其 MemoryScorer 得分可观测到上升
3. 规划界面能展示"该功能涉及 X 聚合，与功能Y存在写冲突"警告
4. 用户能将高置信经验提升为全局经验，并在新项目中被自动召回

---

## 约束

- 不新增外部依赖
- 不改变前后端通信协议（新增字段用 optional）
- 经验自动提升阈值可配置（config.py 新增 experience_promotion_threshold）
