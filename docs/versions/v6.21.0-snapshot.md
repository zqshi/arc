# v6.21.0 Snapshot — LLM 链路深化 + 技术债清理

> 状态: 已归档 (2026-07-01)
> 起始 commit: 64da0e1 (激活归档) / 收尾 77dde04 (D1/D3) + refactor (T1)
> 上一版本: [v6.20.0](v6.20.0-snapshot.md)

## 版本目标

把全局默认 LLM 凭证从 config.py env 接通到 DB `llm_providers` (is_default=True), 消除 v6.20 渐进边界; 清理续11 记入的 P2 技术债 (前端组件超限 / 聚合边界评估)。

## 交付内容

- **D1 全局默认凭证接通 DB**: `LLMProviderService` 新增 `resolve_from_project(project, user_id)` + `resolve_default_config(user_id)`, 优先级链: 项目 `llm_provider_id` → 旧明文 `conversation_config["llm"]` → 用户默认凭证 (D1 新增) → None (env 兜底)。Agent 主链路调用方 (`extract_tags` / `_text_only_stream` / `orchestration.execute`) 改走 `adapter_pool.acquire_for_project(dict)`, `_DEFAULT_KEY` (env) 退化为"DB 无凭证"最终兜底。推翻 current.md 原方案 A (lifespan 注入 `_DEFAULT_KEY`) — 发现 `adapter_pool` 全局单例 vs `LLMProvider` per-user 隔离的串台矛盾, 改选请求级解析 (调用方低侵入, 尊重 per-user, 不加重技术债; `conversation_context` 反而移除了直接依赖 `SqlAlchemyLLMProviderRepository`+`crypto`)。7 单测覆盖 resolve 链。
- **D3 pipeline 路径补 llm_provider_id**: `conversation/service.py:_get_llm_config` 对齐 unified 路径 (`conversation_context.get_llm_config`), 修复 v6.20 L5 遗漏 (pipeline 路径原只读明文跳过 `llm_provider_id`)。两处共用 `LLMProviderService.resolve_from_project` 消除重复。
- **T1 前端 10 组件拆分**: 10 个超 300 行 .tsx 抽子组件 (纯结构搬运 JSX 零行为变化), 父组件全 <300 (最大 295) + 11 parts 文件全 <300 (最大 241)。参照 v6.19 `domain-model-tab-parts` 模式。

## 关键技术决策

| 决策 | 理由 |
|------|------|
| 推翻方案 A, 选请求级解析 (选项1) | `adapter_pool._DEFAULT_KEY` 全局单例 vs `LLMProvider` per-user 隔离 (`get_default(user_id)`); 方案 A lifespan 注入在多用户下串台 (lifespan 无用户上下文, 系统多用户 demo/test)。请求级解析调用方拿 dict 走 `acquire_for_project`, env 退化为兜底 |
| D1+D3 统一进 `resolve_from_project` | 两处逻辑同构 (项目 `llm_provider_id` → DB → 明文回退), 抽共用方法消除重复, 加用户默认层 (D1) |
| D1 只改 Agent 主链路核心 | `extract_tags`/`_text_only_stream`/`orchestration` 三处; 辅助模块 (experience/pipeline/template/planning/artifact/gate 等 ~20 处 `create_resilient_adapter`) 仍走 env, 留渐进边界 (验证标准1 只要求 todo/service 主链路) |
| T3 跳过 (既定模式) | `pipeline/hooks.py` 纯函数 + 函数式 db 参数是全项目统一模式 (v6.19 A4 已核实无 DI 容器), 非聚合违规 |
| D2 留下版本 | worker 路径同 D1 per-user 矛盾 + worker 语义 (cheap model 凭证/model 选择) 需产品决策 + `LLMProvider` 可能扩展 `worker_model`, 专项留下版本 |
| T2 留下版本 | 全量值对象化工作量大 (`pipeline_config`/`conversation_config` 嵌套), 现有 entity 方法已封装 merge |

## 遗留问题

- **D2 worker 凭证链路**: per-phase/worker 选用 (`agent_default`/`worker_llm_provider`) 重映射到凭证 id, 保留 env 兜底。需先定 worker 语义 (cheap model 用哪个凭证哪个 model), 可能扩展 `LLMProvider` 加 `worker_model` 字段。留 v6.22。
- **T2 Project dict 值对象化**: `pipeline_config`/`conversation_config` 等嵌套 dict 全量值对象化, 留 v6.22 专项。
- **集成测试 4 失败 (预先存在, 非本版本引入)**: `test_agent_registry_sync::test_db_declarations_override_env` + `test_capability_api`/`test_capability_repository` 3 处, 根因 DB 有 openhands/codex 声明残留 (stash 验证: 移除 v6.21 改动后仍失败)。环境/数据问题, 待清 DB 残留或测试隔离修复。
- 辅助模块 LLM 调用 (experience/pipeline/template/planning/artifact/gate 等) 仍走 env `create_resilient_adapter`, 未接 DB 默认凭证 (D1 渐进边界, 非验证标准)。
- 多 worker 凭证缓存 Redis pub/sub (留增强)。
- OpenHands/Codex 真注入 (blocked runtime, v6.19 遗留)。
