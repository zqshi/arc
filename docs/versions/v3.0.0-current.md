# v3.0.0 Current — 领域模型升级基础设施

> 状态: 进行中
> 起始 commit: 待定
> 前置版本: [v2.9.0](v2.9.0-snapshot.md)
> 升级路径阶段: Phase 1 / 3

## 版本目标

建立领域模型变更的基础设施：版本化快照、评审反馈实体化、闭环流程。
解决当前 `domain_model_validator.py` 评审结果"火后不管"的问题。

## 版本验证标准

1. `project.domain_model` 任何变更自动创建快照，可按版本号回滚
2. `validate_domain_model()` 的 issues 自动持久化为 ReviewFeedback 记录
3. ReviewFeedback 有完整状态流转: pending → accepted/deferred/rejected
4. 变更自动分级: additive / structural / breaking
5. 后端测试全量通过，domain 新增实体/值对象有配套单元测试

## 版本范围

**做什么:**
- 领域模型快照机制 (Project 实体扩展)
- ReviewFeedback 实体 + 仓储 (新增领域模块)
- 变更分级值对象 (ModelChangeScope)
- Validator 闭环改造
- 对应 API 端点 (查看反馈列表、处理反馈、回滚模型)
- 数据库 migration

**不做什么:**
- 影响分析 → v3.1.0
- Todo SUSPENDED 状态 → v3.2.0
- 前端评审反馈 UI → v3.1.0 (本版本仅 API)
- 自动化升级编排 → v3.2.0

## 各任务实施要点

### T1 — Project 实体扩展：快照机制

**改动点:**

1. `domain/project/value_objects.py` 新增:
   - `DomainModelSnapshot` 值对象 (frozen dataclass)
   - 字段: version, content, trigger, trigger_todo_id, created_at

2. `domain/project/entity.py` Project 实体新增:
   - `domain_model_history: list[dict]` 字段 (JSONB 数组)
   - `upgrade_domain_model(new_model, trigger, trigger_todo_id) → int` 方法
   - `rollback_domain_model(to_version: int)` 方法

3. `domain_model_extractor.py` 改造:
   - 当前直接写 `project.domain_model = dm` → 改用 `project.upgrade_domain_model()`

**设计约束:**
- 快照用 JSONB 数组而非独立表 (前期变更频率低, 每项目最多几十次)
- trigger 枚举: "extractor" | "manual" | "upgrade" | "rollback"
- 快照不可修改 (值对象语义)

### T2 — ReviewFeedback 领域建模

**新增模块:** `domain/review/`

```
domain/review/
├── __init__.py
├── entity.py          ← ReviewFeedback 实体
├── value_objects.py   ← ReviewFeedbackStatus, ModelChangeScope, ReviewIssue
└── repository.py      ← ReviewFeedbackRepository 接口
```

**ReviewFeedback 实体核心:**
```
ReviewFeedback:
  id: UUID
  project_id: UUID
  source_todo_id: UUID | None    # 触发评审的需求 (可选)
  model_version: int             # 评审时的模型版本号
  scope: ModelChangeScope        # additive / structural / breaking
  status: ReviewFeedbackStatus   # pending / accepted / deferred / rejected
  issue: ReviewIssue             # 值对象: severity, category, title, detail, suggestion
  resolution_note: str           # 处理备注
  created_at / resolved_at
```

**状态流转:**
```
pending → accepted  (转为升级任务)
pending → deferred  (延迟处理)
pending → rejected  (评审有误, 不处理)
```

### T3 — 变更分级自动分类

**分级规则 (确定性优先, 不靠 LLM):**

| Validator issue.category | issue.severity | 涉及聚合变更类型 | → ModelChangeScope |
|--------------------------|---------------|-----------------|-------------------|
| naming / completeness | info/warning | 字段补充/重命名 | additive |
| tactical | warning | 新增值对象/枚举 | additive |
| tactical | error | 聚合移动/拆分 | structural |
| strategic | error | 限界上下文重划 | breaking |
| strategic | warning | 新增子域 | additive |

实现为规则引擎 (`application/review/classifier.py`), 不调用 LLM。

### T4 — Validator 闭环改造

**当前流程:**
```
validate_domain_model(dm) → dict (丢弃)
```

**目标流程:**
```
ReviewService.validate_and_persist(project_id, dm, db)
  → validate_domain_model(dm)           # 现有逻辑不动
  → classify_change_scope(issue)         # T3 的分类器
  → ReviewFeedback(...).save()           # 持久化
  → return list[ReviewFeedback]
```

**关键**: 不改 `validate_domain_model()` 签名, 在上层 ReviewService 包装闭环逻辑。

### T5 — API 端点

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/projects/{id}/review-feedbacks` | 列表 (支持 status 过滤, 分页) |
| PATCH | `/projects/{id}/review-feedbacks/{fb_id}` | 处理反馈 (accept/defer/reject + note) |
| POST | `/projects/{id}/domain-model/rollback` | 回滚到指定版本 |
| GET | `/projects/{id}/domain-model/history` | 查看快照历史 |

## 对后续版本的约束

- T4 完成后, 所有调用 `validate_domain_model()` 的地方应改为调用 `ReviewService.validate_and_persist()`
- 快照机制建立后, `DomainModelExtractor.extract_and_merge()` 必须走 `upgrade_domain_model()` 路径
- ReviewFeedback 的 `accepted` 状态在 v3.0.0 仅做标记; v3.2.0 才自动触发升级流程

## 与 Phase 2/3 的接口契约

| Phase 2 需要的 | Phase 1 提供的 |
|----------------|---------------|
| 模型版本号 | `project.domain_model["version"]` |
| 变更前后 diff | `domain_model_history[-1].content` vs `domain_model` |
| 反馈列表 (accepted) | `ReviewFeedbackRepository.list_by_status(ACCEPTED)` |
| 受影响聚合名称 | `ReviewFeedback.issue.detail` 中提取 (T3 分类时记录) |

| Phase 3 需要的 | Phase 1 提供的 |
|----------------|---------------|
| 回滚能力 | `Project.rollback_domain_model(version)` |
| 快照审计 | `Project.domain_model_history` |
| 反馈→任务转化起点 | `ReviewFeedback(status=ACCEPTED)` |
