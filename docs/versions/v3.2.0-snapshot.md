## 版本目标

把影响分析的决策转化为系统可执行的动作：暂停受影响需求、执行模型升级、恢复需求。

## 交付物

1. **Todo SUSPENDED 状态**: 状态机扩展 ACTIVE→SUSPENDED→ACTIVE，suspend/resume 方法
2. **UpgradeStrategy**: block (阻断升级) / defer (延迟) 两种策略
3. **ModelUpgradeOrchestrator**: 全流程编排 — 影响分析→暂停高风险→升级模型→标记反馈→恢复低风险
4. **API**: POST /domain-model/upgrade + POST /todos/{id}/resume
5. **+20 tests** (948 total)

## 关键决策

| 决策 | 选项 | 理由 |
|------|------|------|
| 暂停 vs 阻断 | SUSPENDED 新状态 vs 复用 ERROR | SUSPENDED 语义清晰：主动暂停，有明确恢复条件；ERROR 是异常 |
| 自动恢复范围 | 低风险自动 + 高风险手动 | 避免全自动恢复遗漏需要人工审视的需求 |
| 升级入口 | 用户主动 POST vs 自动触发 | 第一版保守：用户决策后主动发起，后续可加自动策略 |
