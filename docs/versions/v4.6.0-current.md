## 设计要点

### T1: 按钮三态

版本卡片上的 AI 分析按钮根据状态显示不同文案和样式：

| 状态 | 条件 | 按钮展示 | 行为 |
|------|------|---------|------|
| 无分析 | `!has_analysis` | 「✨ AI 分析」蓝色 | 触发生成 |
| 有分析且无变更 | `has_analysis && !fingerprint_changed` | 「📄 查看报告」灰色 | 直接展示缓存 |
| 有分析但已变更 | `has_analysis && fingerprint_changed` | 「🔄 重新分析」橙色 | 提示后重新生成 |

**后端改造**: list_versions 返回 `analysis_stale: bool`（当前 fingerprint 是否与最新分析的 fingerprint 不同）

### T2: 结构化提取

分析结果 markdown 中的"行动建议"表格解析为结构化数据：

```json
{
  "suggestions": [
    {"priority": "P0", "action": "接入真实平台 API", "reason": "打通比价→预定的真实链路"},
    {"priority": "P1", "action": "强制 Supabase 用于 staging", "reason": "验证数据持久化"}
  ]
}
```

**解析策略**: 后端 AI 生成时要求输出特定格式（在 prompt 中约束），或后处理时用正则/LLM 提取。

### T3: 一键填充

分析弹窗底部新增「行动建议」区域：
- 每条建议显示为 checkbox 列表
- 用户勾选后点击「创建为需求」
- 自动创建 todo 到下一个 planning 状态的版本（或当前版本）
- 创建后建议标记为"已转需求"

## 约束

- planning_service 拆分保持接口不变，只是文件级重组
