## 关键决策

1. **LLM 驱动校验 vs 规则引擎**: 选择 LLM — 规则会遗漏, LLM 理解上下文语义, 覆盖更全面
2. **DDD 三阶段自主性**: AI 自主驱动一次性完成, 不等用户确认 — 减少交互摩擦
3. **alembic migration 策略**: 只做 nullable 收紧 + 索引新增, 不删除任何已有索引 — 安全优先
4. **E501 处理**: 内联 CSS / prompt 模板配置 per-file ignore, 代码逻辑行拆分 — 可读性优先

## 对后续版本的约束

- DDD prompt 中的 event_storming schema 已发布, 后续 tech_architecture 产出物将包含 events/commands 字段
- 领域模型校验用 LLM 驱动, 后续可扩展为对话式改进 (用户可针对 issue 要求 AI 修正模型)
- ORM 模型仍有部分索引声明与数据库不一致, 后续版本应在模型中补回 `index=True`
- extract_and_merge 已引入 deepcopy 快照比较, 确保幂等性
