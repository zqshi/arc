## 版本目标

收口 G1 A 留下的 B/C 类: template services (B) 复制 G1 A 的 resolve_for_context 模式; gate/validator 纯函数 (C) 按 v6.23 决策**注入 adapter**。完成后全代码库 LLM 调用统一走 DB 凭证 (除 adapter_pool 内部工厂), 设置页凭证对所有链路生效。

## 版本验证标准

1. template matching/apply/extraction 走 DB 凭证 — 设置页配的 per-user 凭证对模板链路生效 (None 时 env 兜底)
2. 各 gate/validator (evaluate_gate/evaluate_sufficiency/evaluate_conversation_gate/validate_domain_model/llm_review) 接受调用方注入的 adapter, 不再裸 `create_resilient_adapter()`
3. `grep create_resilient_adapter\( backend/src/arc/application` 仅命中 adapter_pool 内部 (工厂实现), 无业务调用点散落

## 版本范围

**做什么:**
- G1-B: template {matching,apply,extraction}Service 复制 G1 A (resolve_for_context + acquire_for_project)
- G1-C: 5 个 gate/validator 纯函数注入 `adapter` 参数 + 调用方 (ExecutionEngine/PipelineService 等) acquire_for_project 后传入; analysis_service L160 env fallback 收口

**不做什么:**
- R1-R5 端到端 → blocked 外部环境 (PAT/S3/runner/证书), 非 dev 可解
- 多 worker Redis pub/sub → 增强项, 单 worker 不触发
- 重命名 COMPOSE_ 前缀 (D1 B 类) → breaking 大收益低, 留专项

## 关键技术决策 (已定, v6.23 末)

- **C 类注入 adapter (非 llm_config, 非 db)**: gate/validator 是纯函数无 db, 注入 `adapter: LLMAdapter` 保持纯函数 + 零 DB 耦合 + 最易测。调用方 (ExecutionEngine) `async with adapter_pool.acquire_for_project(cfg) as ad: result = await evaluate_gate(..., adapter=ad)`。
- **B 类复制 G1 A**: template services 是 service 类 (有 db), 直接 `resolve_for_context` + `acquire_for_project`, 无架构决策。

## 各任务实施要点

### G1-B (template services)
- 核实 3 个 service 是否持有 db + project_id/user_id (或调用方传入); 若无, 沿 G1 A 模式从调用方接 db。
- extraction_service 有 2 个 create_resilient_adapter 站点 (L159/L243), 都收口。
- TDD: 每个服务 mock acquire_for_project 验证透传 llm_config (同 G1 A 测试范式)。

### G1-C (gate/validator 注入)
- 5 纯函数加 `adapter: LLMAdapter` 必填参数 (或 `adapter` + 保留 None 时内部 create_resilient_adapter 兜底? **不兜底** — 强制注入, 消除散落)。
- 内部 `create_resilient_adapter()` 调用删除, 直接用传入 adapter。
- 调用方排查: `evaluate_gate` ← pipeline/service._evaluate_phase_gate; `evaluate_conversation_gate`/`evaluate_sufficiency`/`validate_domain_model`/`llm_review` ← execution engine 链路。调用方须先 acquire_for_project 取 adapter 再传入。
- analysis_service L160 fallback: 核实 L144/146/153/155 已用 project config, L160 是无 project 时的 env 兜底 → 收口为注入或保留 env (视调用方是否总有 project)。
- TDD: 每个纯函数单测改传入 fake adapter (零 mock create_resilient_adapter)。
