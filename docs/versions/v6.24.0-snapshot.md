### strict gate 死循环修复 (P0+P1+P2)

- **P0 passed 改 score 驱动 (5c77641)**: `pipeline/gate.py:149` 吃 LLM `passed` 字段 (无 rubric 时 LLM 倾向 `passed=False` 即使 score=9) → strict clarification 永久卡死。改 `passed = (结构无缺口 且 无p0 且 score>=阈值)`, 对齐 `conversation_gate`; 解析失败 `review_infra_failure` 哨兵; `evaluate_gate` 加 `llm_review_fn` 注入; gaps `dict.fromkeys` 去重保序。比 backlog "score 阈值+2 兜底" 更彻底。
- **P1 GATE_EVALUATION_PROMPT rubric 化 (483a032)**: 加评分维度 (完整性0.3/一致性0.25/可行性0.25/清晰度0.2) + score 9-10/7-8/5-6/3-4/1-2 锚点 + `p0_gaps`(阻断)/`gaps`(建议) 分级 + **删 `passed` 输出字段**。pipeline/gate + conversation_gate 同步读 p0_gaps 致 fail。
- **P2 confirm 评审故障逃生阀 (9194378)**: `GateResult` 加 `review_infra_failure` 字段 (比 score==0 精确 — DAG 失败也 score=0); `confirm_phase` 加 `force_review_failure`+`reason` (keyword-only), **仅 `review_infra_failure=True` 可 force** (客观守卫 结构/方法论/DAG 不可绕过); reason 空→400, 客观 fail+force→409; `logger.warning` 审计 (不加 DB 字段/migration)。重定义 "质量 override" 为 "故障逃生阀" 化解 STRICT 语义冲突。

## 关键技术决策

| 决策 | 理由 |
|------|------|
| strict gate passed 改 score 驱动 (非"阈值+2 兜底") | 直接不读 LLM `passed` 字段, 比 backlog 兜底方案更彻底; pipeline 与 conversation 两路径统一 |
| `review_infra_failure` bool 哨兵 (非 score==0) | DAG 守卫失败也 score=0, score 无法区分 "客观 fail" vs "LLM 故障"; 哨兵字段单一职责 |
| P2 "故障逃生阀" 重定义 (非"质量 override") | STRICT 承诺 "不可绕过质量门", override 违背语义; 重定义为 "LLM 评审基础设施故障逃生" (仅 `review_infra_failure` 可 force, 客观守卫保留), 化解冲突 |
| GATE_EVALUATION_PROMPT 删 passed 输出字段 | 消除 "LLM 自评 passed 与 score 矛盾"; passed 完全由代码 score 推导, 单一真相源 |
| BaaS provision 预建 Supabase 约定用 IF NOT EXISTS | CREATE OR REPLACE 污染 Supabase 内置 auth.uid(); IF NOT EXISTS 内置环境跳过, dev 兜底建 |
| 推翻 R5 "blocked 构建凭证" | R5 不依赖构建凭证 (那是 R3/R4), 只需 LLM + provision; backlog 标注过时, 实测验证 |
