# v0.4.0 Snapshot — Agent生态与需求编排

> 发布日期: 2026-05-21
> 起始 commit: c377193 | 末尾 commit: 823da07
> 上一版本: [v0.3.0](v0.3.0-snapshot.md)

## 版本目标

让 Arc 的 Agent 执行能力从"只有 OpenHands"扩展为多选项(Claude Code 优先), 同时为需求之间建立依赖关系, 让规划引擎能感知任务顺序。

## 交付内容

- **Agent 适配器扩展**: Claude Code（subprocess + JSON 解析）、Codex（Responses API）两个新适配器上线, 均实现 `CodingAgentAdapter` 五方法接口
- **需求依赖关系**: `todo_dependencies` 表 + CRUD API + 前端阻塞状态展示（Lock 图标 + 阻塞标签）
- **同版本需求感知**: `ProjectContextProvider` 自动查询并注入 sibling_requirements, 对话和 Agent 执行均可感知
- **项目仪表盘**: 聚合 API（需求统计 / 版本进度 / Agent 执行 / 最近活动）+ DashboardTab 前端页面
- **Agent 集成测试**: Claude Code 适配器 6 项测试（启动 / 状态 / 事件 / 取消 / 增量 / 异常）
- **版本管理体系**: docs/versions/ 目录 + CLAUDE.md 跨会话上下文注入协议
- **v0.3.0 遗留清理**: DB 索引 migration 幂等化, TodosTab/TodoSidebar 交互优化

## 关键技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| Claude Code 集成方式 | subprocess + `--print --output-format json` | 非交互模式, 可解析结构化输出, 无需 WebSocket |
| Codex 集成方式 | httpx + OpenAI Responses API | API 驱动, 无需本地安装 CLI |
| 依赖关系数据模型 | 独立 `todo_dependencies` 关联表 | 避免 Todo 表膨胀, 支持级联删除, 自引用 CHECK 约束 |
| 仪表盘数据源 | 数据库聚合查询（非中间件） | 简单直接, 无额外基础设施依赖 |
| 同版本感知注入点 | ProjectContextProvider 统一注入 | 对话服务和 Agent 执行共用同一上下文组装 |

## 遗留问题

- 无

## 对后续版本的约束

- Agent 适配器必须遵循 `CodingAgentAdapter` 接口, 不允许绕过
- 依赖关系目前只支持 "blocked_by" 单一关系类型, 不做复杂依赖类型
- 仪表盘数据用数据库聚合查询, 不引入额外的统计中间件
- 新 Agent 适配器注册需在 `registry.py` 的 `create_agent_registry()` 中添加条件注册逻辑
