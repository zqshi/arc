## 各任务实施要点

### D2 — worker 凭证链路 (v6.21 遗留)

**现状**: `acquire_worker` → `_WORKER_KEY` → `_create_worker_adapter` (读 `settings.worker_llm_provider`/`worker_model` env)。同 D1 per-user 矛盾 (worker 路径全局 `_WORKER_KEY`, 凭证 per-user)。

**待定 worker 语义** — cheap model 用哪个凭证哪个 model? 候选:
- (a) 用户默认凭证的某 model (`resolve_default_config` + 指定 worker model)
- (b) 单独 worker 凭证指针 (`Project.worker_provider_id` 或 `LLMProvider.worker_model` 字段)
- (c) 保留 env `worker_model` + DB 凭证 (割裂, 语义怪)

需产品决策后选定。倾向 (a) 最简 (复用 D1 用户默认凭证, worker 用其 models 列表中某 cheap model)。

### T2 — Project dict 值对象化 (v6.21 遗留)

评估 `pipeline_config`/`conversation_config` 哪些 dict 值得值对象化。现有 entity 方法 (`update_pipeline_config`/`update_phase_capabilities` 等) 已封装 merge, 评估 ROI 后定范围。

### T5 — 集成测试 4 失败修复 (预先存在, 非 v6.21 引入)

`test_agent_registry_sync::test_db_declarations_override_env` + `test_capability_api::test_create_and_get`/`test_list_with_filter` + `test_capability_repository::test_list_with_filters`。根因 DB 有 openhands/codex 声明残留 (之前测试或 seed 加的未清理)。修复策略: 清 DB 残留 或 测试隔离 (conftest savepoint, v6.16 模式)。
