# v2.5.0 Current — Context Engine (上下文引擎)

> 状态: 进行中
> 起始日期: 2026-05-31
> 上一版本: [v2.4.0](v2.4.0-snapshot.md)

## 版本目标

v2.4.0 加固了底盘，但产品核心卖点"上下文零断裂"缺乏技术基座：对话历史直接全量发送 LLM，无 token 预算控制、无压缩、无缓存感知。本版本目标是构建 **上下文引擎** — 从 Harness 知识体系引入 Context Control + Compression + Prompt Cache 三大模块。

## 版本验证标准

1. 20+ 轮对话不爆 context window（从 DB 验证消息保留、从日志验证压缩触发）
2. conversation_strategy.py 从 669 行拆分为 3 个文件，每个 < 300 行
3. Anthropic API 响应中出现 `cache_read_input_tokens > 0`（Prompt Cache 命中）
4. 工具输出超 10K 字符时自动 L1 压缩（日志可验证）
5. 现有测试全部通过

## 版本范围

**做什么:**
- ContextController 上下文装配器（token 预算、优先级淘汰）
- CompressionManager 三级压缩（L1 微压缩 + L2 段落 + L3 全量）
- Prompt Cache 感知（Anthropic cache_control + 缓存友好排序）
- conversation_strategy.py 拆分（669 → 3 文件）
- tool_loop L1 压缩集成

**不做什么:**
- Verify Loop → v2.6.0
- Drift / Error Loop 检测 → v2.6.0
- Memory 打分算法 → v2.7.0

## 各任务实施要点

### T4 — conversation_strategy.py 拆分

**目标**: 消除 God Class，为 ContextController 集成腾出空间。

**拆分方案**:
1. `context/prompt_builder.py` — `_build_system_prompt()`, `_build_llm_messages()`, experience/DDD/artifact 上下文组装
2. `execution/execution_engine.py` — `generate_response_stream()`, `run_autopilot()`, tool/text path 分发
3. `execution/conversation_strategy.py` — `initialize()`, tracker 管理, config 读取

### T1 — ContextController 上下文装配器

**来源**: Harness §2 Context Control

**要点**:
- Token 预算分配 (system 3K + memory 6K + recent 40K + tool_results 60K + older 40K + reserve 40K)
- 70% 触发 L2，85% 触发 L3
- 快速 token 估算 (字符数 / 3.5 中文, / 4 英文)
- 集成点: 替换原 `get_context_window(max_messages=50)` 硬编码

### T2 — CompressionManager 三级压缩

**来源**: Harness §3 Compression

**要点**:
- L1: head 3000 + tail 2000 + 中间摘要
- L2: LLM 摘要早期对话，必须保留失败记录
- L3: 重建最小上下文 (< 2000 tokens)

### T3 — Prompt Cache 感知

**来源**: Harness §13 推理优化

**要点**:
- Anthropic system 消息添加 `cache_control: {"type": "ephemeral"}`
- 上下文排序: 静态 prompt → 工具定义 → 项目上下文 → 对话历史 → 用户消息

### T5 — tool_loop L1 压缩

**要点**:
- ToolAwareLoop 构造函数新增 `compression: CompressionManager = None`
- tool result > 10K 字符 → 自动 L1 压缩

## 对后续版本的约束

- ContextController 建立后，所有 LLM 调用必须走 ContextController.assemble()
- CompressionManager 接口稳定后，后续版本只增加压缩策略不改接口
- Prompt Cache 排序约束：静态内容必须放在 system prompt 前段
