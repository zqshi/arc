# v1.0.0 Snapshot — 多用户与团队

> 发布日期: 2026-05-21
> 起始 commit: 894b979 | 上一版本: [v0.5.0](v0.5.0-snapshot.md)

## 版本目标

从单人工具扩展为小团队协作平台。引入角色权限、项目成员管理, 经验在团队内共享但个人经验保持私有。

## 交付内容

- **角色权限体系**: UserRole 枚举 (admin/member/viewer), User model role 字段, migration
- **项目成员管理**: ProjectMemberRepository CRUD, 成员邀请/移除/角色变更 API, 创建项目自动加入创建者
- **权限中间件**: require_project_role 依赖注入, 成员管理写操作需 admin 权限
- **项目成员前端**: MembersTab 组件 (成员列表/添加/角色变更/移除), 集成到 ProjectDetail
- **前端权限渲染**: 根据用户项目角色控制操作按钮显隐 (viewer 只读, member CRUD, admin 管理)
- **经验访问控制**: 项目经验团队成员可见, 个人经验仅创建者可见, 搜索范围按成员关系限定
- **团队经验复用**: 经验库 scope 筛选, 成员间经验发现

## 关键技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 角色模型 | 系统级 UserRole + 项目级 project_members.role | 系统角色提供全局默认, 项目角色支持细粒度控制, 预留自定义角色扩展 |
| 权限实现 | Depends 依赖注入, 非装饰器 | 与 FastAPI 生态一致, 可组合, 支持运行时动态检查 |
| 项目可见性 | OR(owner, member) 查询 | 兼容存量数据 (旧项目仅有 owner), 新项目创建时自动加入 members |
| 经验访问控制 | 基于 project_members 子查询 | 数据库级过滤, 无需额外缓存, 成员变更即时生效 |
| 前端权限 | myRole state + canWrite prop | 轻量, 不引入额外状态管理, tab 级过滤 + 按钮级控制 |

## 遗留问题

- 存量项目的 owner 不在 project_members 表中 (代码已兼容, 但建议数据迁移补齐)
- 角色变更无审计日志
- 邀请成员需要知道用户 ID, 暂无搜索/邀请链接机制

## 对后续版本的约束

- 角色枚举 UserRole 需预留扩展点 (自定义角色 → v2.0)
- project_members 表需支持团队级操作 (批量邀请等)
- 经验访问控制逻辑需与未来的 "经验模板市场" 兼容 (public scope)
- require_project_role 中间件的 owner fallback 逻辑在 members 数据完善后应移除
