## 版本目标

让用户能在设置中添加多个大模型厂商配置 (各自 base_url + API key + 模型清单), 填 base_url 拉取真实模型清单, 填 API key 真实鉴权验证, 从中选用全局默认 / 项目级覆盖。解决现状三大缺口 (模型清单写死 / key 只判非空 / provider 硬编码) + 一个安全问题 (项目级 api_key 明文存 conversation_config) + 死字段 (temperature/max_tokens 无落点)。

## 版本验证标准

1. 设置页可添加/编辑/删除多个 LLM 厂商配置, 每个独立验证
2. 填 base_url + API key → 点验证 → 后端真实探活 → 成功回填该端点真实模型清单 (OpenAI 兼容走 `models.list()`) / 失败显示具体错误 (401/网络/超时)
3. 全局默认 + 项目级覆盖 (`Project.llm_provider_id`) 选用链路打通, Agent 调用走选中凭证
4. 质量检测 6.1-6.7 全过, 现有 v6.19 链路零回归

## 数据模型

```
llm_providers 表 (migration z23):
  id (uuid pk)
  user_id (fk users, index)            # 用户级隔离
  name (str)                            # 别名 "我的OpenAI"/"国内代理"/"本地ollama"
  kind (str: openai_compatible | anthropic)   # 协议族, 决定 adapter + 是否支持 list_models
  base_url (str)
  api_key_enc (text, Fernet 加密)       # 复用 crypto.encrypt/decrypt, 注入式
  models (json [], 缓存的模型清单)      # verify 时拉取
  is_default (bool, default false)      # 该用户全局默认 (部分唯一索引: user_id + is_default=true 至多一)
  created_at / updated_at
```

**选用关系**:
- 全局默认 = 该用户 `is_default=True` 的凭证
- 项目级覆盖 = `Project.llm_provider_id` (fk → llm_providers.id, nullable) 指向该用户某条凭证, **替代** 现状 `conversation_config["llm"]` 明文 dict (顺带修安全问题)

## 关键决策 (已定)

1. **凭证归属**: 用户级 (`user_id` 隔离), 符合"我的厂商 key"语义
2. **加密**: 复用 `crypto.py` Fernet (同签名凭证), dev 降级明文
3. **同步 vs 异步**: `adapter_pool._adapters` 内存缓存预加载, 规避全链路 async 改造
4. **verify 验临时凭证**: 前端传 `{kind,base_url,api_key}`, 后端构造临时 adapter 探活, 成功顺带返 models
5. **Anthropic 无 list API**: 静态建议降级, UI 诚实标注
6. **config.py 字段降级为 env seed/fallback** (向后兼容)
7. **项目级改 `llm_provider_id` 指针** (替代明文 dict, 顺带修安全问题)

## 复用的既有实现 (不要重造)

- `infrastructure/crypto.py` `encrypt/decrypt` (Fernet, api_key 加密)
- `domain/project/entity.py:167` 签名凭证 `set/get_*_creds(encrypt_fn/decrypt_fn)` 注入式模式
- `application/ai/adapter_pool.py` `_adapters` 缓存 + `_ensure_adapter` (规避 async DB 读)
- `application/settings/service.py` 失效缓存模式 (凭证 CRUD 后清 adapter 缓存)
- `infrastructure/ci/github_actions_client.py` MockTransport 注入单测模式
- `application/build/readiness_cache.py` 进程内 TTL 缓存模式 (models 清单缓存)
- `interface/routes/settings.py` GET 返 `api_key_set` bool 不回明文模式

## 对后续版本的约束

- LLM 凭证统一走 DB `llm_providers` 表 (Fernet 加密), 禁止再明文存 api_key (含 `conversation_config`)
- provider 列表单一真相源 = `PROVIDER_TEMPLATES` (domain), 前后端共享, 禁止前后端各自硬编码
- adapter 探活能力 (`list_models`/`verify`) 是 adapter 接口契约一部分, 新增 provider 适配器须实现
- 延续 v6.19 及之前既定约束 (新增 BuildTarget 同步 12+1 注册点 / 先 artifact 后 runtime / CI 编排不扩 SandboxRuntime / import 环契约工厂分离 / .env dict 禁裸空值)

## 遗留 (本版本可能留)

- per-phase/worker 选用重映射完整形态 (L5 评估, 保留 env 兜底)
- 多 worker 凭证缓存一致性 (Redis pub/sub, 留增强)
- Anthropic 模型清单只能静态建议 (官方无 list API, 诚实降级)
- **全局默认凭证读取边界 (L5 渐进)**: `create_llm_adapter()` 同步读 config.py env, 未接 DB 默认凭证 (同步函数无法 async 读 DB)。当前状态: DB 凭证管理 + 项目级 `llm_provider_id` 指针全通 (新链路走 DB), 全局默认仍走 env fallback (向后兼容)。完整接通全局默认走 DB 需 `create_llm_adapter()` 异步化或 adapter_pool 预加载 DB 默认凭证, 留后续 (同 plan "同步 vs 异步" 决策的延伸, 评估后判定渐进边界更稳妥)。
