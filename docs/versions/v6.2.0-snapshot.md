## 版本目标

为 BINARY_APP 构建产物加上分发层：商店上传 + 制品分发层（下载页/更新元数据生成）。凭证可配置、非阻塞——未配凭证 skip 商店上传，产物落制品仓可手动下载。

## 关键决策

- **Distributor 抽象同构 Signer**: domain 定义 Distributor 契约 + DistributorType + DistributionCredentials 值对象, infrastructure 实现各渠道分发器, `__init__` 注册表 (与 v6.1 Signer 同构)
- **分发凭证项目维度加密存储**: 复用 v6.1 crypto 基础设施, 独立 enc_appstore/playstore/tauri_updater_creds 字段 (与签名凭证分离)。play_key_json 从 v6.1 SigningCredentials 归位到 DistributionCredentials (它本就是分发凭证)
- **T3 Play Console 用 jose RS256, 不引入 PyJWT**: 复用 pyproject 已有 python-jose[cryptography] (v6.1 引入), jose 支持 RS256。纠正"T3 需 PyJWT"的旧评估
- **play_package_name 补字段**: Play Developer API edit 必需 packageName, 当前 DistributionCredentials 只有 play_key_json。补 play_package_name (与 key_json 一起加密存 enc_playstore_creds, entity/migration 透明不改)
- **T5 artifact 显式建模**: DistributionManifest/ArtifactEntry/DistributionOutcome 三个值对象, 把"签名后产物分发"结果显式建模 (符合"先 artifact 后 runtime")。DB 持久化 manifest JSON + 制品仓渲染双写
- **distributor 接入 deploy 流程 graceful 不阻断**: DeployService._distribute 在 deployer 后编排 (build_manifest→distribute→generate→publish), 任何异常不阻断 deploy (产物已落制品仓可手动下载)
- **签名平台 ≠ 分发渠道 (两维度)**: .app 走 APPLE 签名但走 TAURI_UPDATER 分发; .ipa→APP_STORE; .apk→PLAY_STORE。签名状态按产物路径匹配 sign_results, distributor 按产物后缀选渠道
