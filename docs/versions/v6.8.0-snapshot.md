## 版本目标

补全 Arc 的"能力运行时入口": agent/skill 可声明管理(DB 持久化), 项目按环节(固定7阶段)配置可用能力, 执行时按环节注入, 门禁按环节能力生成检查项。收敛自需求评审: 环节内能力可配(非环节自定义, 保研发链路定位) + skill=SKILL.md 能力封装 + MCP 不做(预留扩展位) + 门禁走 LLM 延伸(非规则引擎)。

## 关键决策

- **统一能力注册表**: agent+skill 两类型复用 SIGNERS 注册表模式, 不为 MCP 单建(type 预留 CapabilityType.MCP, loader 不实现)
- **环节内能力可配**: 固定7阶段(VALID_PHASES 单一事实源, 派生自 enabled_phases), 每阶段配 agent/skill, 非环节自定义(保研发链路定位)
- **执行注入走 Provider 管道**: plan 原写 execution_engine._tool_aware_stream 注入, 代码核查发现该方法只拿现成 llm_messages、无 phase、不组 prompt(文件 570 行警告区)。phase 实际在 PromptBuilder.build_system_prompt 推断、经 ContextRequest 传 ContextAssembler Provider 管道。故新增 CapabilityProvider 走 Provider 管道(第10个 provider), 不动 execution_engine, 符合"复用>新建"
- **门禁 LLM 延伸**: conversation_gate capabilities_section(charter 门禁同构), 非规则引擎
- **type-phase 不硬匹配**: skill 通用性, 改门禁 LLM 软约束
- **顺带修复**: update_pipeline_config 重置式→增量深度 merge(部分更新不丢已配字段); 全局 DomainError→400 exception handler(原落 500, baas/template/capability 均受益); 新增 CapabilityService.list_by_ids(W3.1/W3.2/W3.3 共用)
