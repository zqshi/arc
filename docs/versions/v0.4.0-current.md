# v0.4.0 Current — Agent生态与需求编排

> 状态: 进行中
> 起始: 2026-05-21
> 上一版本: [v0.3.0](v0.3.0-snapshot.md)

## 版本目标

让 Arc 的 Agent 执行能力从"只有 OpenHands"扩展为多选项(Claude Code 优先), 同时为需求之间建立依赖关系, 让规划引擎能感知任务顺序。

## 版本验证标准

1. 用 Claude Code 执行一个完整的开发任务(从待办卡片出发, Agent执行, 结果回写)
2. 两个需求之间可以设置依赖关系, blocked 的需求在UI上有明确提示
3. AI对话时能感知同版本其他需求的存在, 避免方案冲突

## 版本范围

**做什么:**
- Claude Code 适配器实现 (P0)
- Codex 适配器实现 (P1)
- 需求依赖关系 (P1)
- 同版本需求感知上下文注入 (P2)
- 项目仪表盘基础版 (P2)

**不做什么:**
- Cursor适配器 → 等官方API稳定
- 经验衰减/提炼 → v0.5.0
- 多用户/权限 → v1.0
- Agent多步骤编排/自动retry → v0.5.0+ (二代预留)

## 各任务实施要点

### T1 — Claude Code 适配器 (P0, 关键路径)

**接口**: 实现 `CodingAgentAdapter` 的5个方法 (start/get_status/get_events/cancel/close)

**实现方案** (来自 agent-upgrade-plan.md):
- 通过 `asyncio.create_subprocess_exec` 启动 `claude` CLI
- 使用 `--json` 模式获取结构化输出
- 解析 stdout 为 AgentEvent 流
- 通过 SIGTERM 实现取消
- 工作目录由 `settings.claude_code_work_dir` 控制

**配置项需新增**: `claude_code_path`, `claude_code_work_dir`, `claude_code_model`

**注意**: 目标机器需安装 Claude Code CLI (`claude` 命令可用)

### T3 — 需求依赖 DB 层

**数据模型**:
```sql
CREATE TABLE todo_dependencies (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    todo_id UUID NOT NULL REFERENCES todos(id) ON DELETE CASCADE,
    depends_on_id UUID NOT NULL REFERENCES todos(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ DEFAULT now(),
    UNIQUE(todo_id, depends_on_id),
    CHECK(todo_id != depends_on_id)
);
```

**Domain变更**: Todo entity 增加 `blocked_by: list[UUID]` 和 `blocks: list[UUID]`

### T7 — 同版本需求感知

**改动点**: `ProjectContextProvider.get_project_context()` 已返回 `sibling_requirements`, 但当前对话服务的 system prompt 模板中未使用这个字段。

需要在 `application/execution/prompts.py` 或 `application/conversation/service.py` 的 `_build_system_prompt` 中, 将 sibling_requirements 注入为:
```
## 同版本其他需求
以下是同版本正在进行的其他需求, 生成方案时注意避免冲突:
- [标题] (状态: xxx)
- [标题] (状态: xxx)
```

## 对后续版本的约束

- Agent适配器必须遵循 `CodingAgentAdapter` 接口, 不允许绕过
- 依赖关系目前只支持 "blocked_by" 单一关系类型, 不做复杂依赖类型
- 仪表盘数据用数据库聚合查询, 不引入额外的统计中间件
