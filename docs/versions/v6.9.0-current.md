## 修复方案(方案 E — 纯测试侧)

- **否决方案 A**(/health 走 `Depends(get_db)`): 破坏 /health"总返回 200+status"语义 — `get_db` 连接获取异常在依赖解析阶段抛出, 冒泡 500(原 `async with async_session_factory()` 在函数体 try/except 内, 捕获为 degraded 200)
- **方案 E**: conftest `client` fixture monkeypatch 全局 `async_session_factory` 为复用 `db_session` 独立 engine 的测试 factory, /health 与全局 engine 解耦
- **不改业务代码**: /health 仍用全局 factory(生产语义不变), 仅测试隔离
- **degraded 路径覆盖**: `test_health_degraded_when_db_error` monkeypatch factory 注入抛异常 session, 验证 /health 捕获降级(200+degraded 非 500)
