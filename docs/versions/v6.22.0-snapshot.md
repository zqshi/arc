## 交付内容

- **T5 集成测试 4 失败修复**: 根因 dev DB 预存 openhands 脏数据 + 三文件本地 `cleanup` teardown 模式 (yield 在前, v6.16 savepoint 下 commit 退化、DELETE 被外层 rollback 撤销, 从未真正清理)。修复: 提取到 `conftest.py` 统一 `cleanup` fixture 改 setup 模式 (DELETE+flush 在 yield 前), savepoint 内 teardown rollback 不破坏 dev DB。附带 `test_db_empty_seeds_env`/`test_seed_idempotent` 不再因脏数据巧合通过, 真正测到 env seed 路径。
- **D2 worker 凭证链路走 DB**: 选方案 (a) 复用主凭证 + `settings.worker_model` 覆盖。`acquire_worker(llm_config)` 接受 D1 透传的 llm_config: 有 api_key → `_create_worker_adapter(llm_config)` 复用 provider/api_key/base_url + worker_model 覆盖 model (cheap), ephemeral 不缓存 (同 acquire_for_project); None/无 api_key → fallback `_WORKER_KEY` (env 兜底)。调用方仅 `orchestration/service.py _run_worker` 传 `self._llm_config`。6 unit 测试。
- **T6 403 重试致 scan 409 (计划外)**: `resilience._retry`/`chat_stream`/`chat_stream_with_result` 对所有异常重试 (含 403), scanner_analysis 5 处 LLM 调用 × 3 重试 × 指数退避致后台 scan task 长时间占位, `is_running=True` → 再点 → 409。加 `_is_retryable_error(exc)` helper, 4xx (非 429) 客户端错误不重试立即抛出。2 unit 测试。
- **T7 扫描接 DB 凭证 (计划外, B)**: scanner_analysis 5 处 `acquire()` → `acquire_for_project(llm_config)`; scan_codebase 路由 `resolve_from_project(project, user.id)` → llm_config 透传 start_scan→_run_scan→scan_and_summarize_stream。扩展 D1 边界 (原"辅助模块不做"), None 时 env 兜底。3 unit 测试。
- **T8 force=true 强制重扫 (计划外, A)**: scan_manager 加 `cancel(project_id)` (pop task + cancel + await, 不在 lock 内 await 避与 _run_scan finally 死锁); scan_codebase force=true 时 cancel 旧 task 再 start_scan, 非 force 仍 409。scan_status 残留由路由补偿置 idle。unit 测试覆盖 cancel。
- **T2 Project dict 值对象化评估**: 评估后不做 (pipeline_config ROI 低 / domain_model ROI 负 (LLM 产出) / conversation_config 整体值对象化绑死迁移期兼容结构)。记技术债务: 下版本按需取 conversation_config 的 git_sync/loop_config 子结构值对象化。

## 关键技术决策

| 决策 | 理由 |
|------|------|
| D2 选方案 (a) 复用主凭证 + worker_model 覆盖 | worker 调用方仅 orchestration `_run_worker`, 已持有 `self._llm_config` (D1 resolve_from_project 透传); 复用主凭证 + settings.worker_model 覆盖 model 最简, per-user 隔离同 D1; None 时 env 兜底保持渐进边界 |
| T5 conftest 统一 cleanup 改 setup 模式 | 三文件本地 cleanup 为 teardown (yield 在前), v6.16 savepoint 下 commit 退化、DELETE 被外层 rollback 撤销从未真正清理; 改 setup (DELETE+flush 在 yield 前) 根治, savepoint 内 teardown rollback 保护 dev DB |
| T6 4xx (非 429) 不重试 | 403/400 等客户端错误重试无意义 (权限/参数错误), 盲目重试致后台 task 占位 → is_running → 409; 立即抛出快速释放 |
| T7 扫描接 DB 凭证 (扩展 D1 边界) | 用户实测扫描走 env 403 (env model 未启用), DB 凭证对扫描无效 (D1 原列"辅助模块不做"); resolve_from_project 透传让设置页凭证生效, None 时 env 兜底兼容 |
| T8 force=true cancel 旧 task | force 原只跳指纹缓存不跳 is_running, 卡住时无法强制重扫; cancel 取消旧 task (不在 lock 内 await 避死锁) |
| T2 不做 | pipeline_config 键已由 VALID_PHASES 约束 (ROI 低); domain_model LLM 产出与意图驱动哲学冲突 (ROI 负); conversation_config 整体值对象化绑死迁移期兼容结构 |
