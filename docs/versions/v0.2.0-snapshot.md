# v0.2.0 Snapshot — 认证体系与安全加固

> 发布日期: 2026-05-18
> 对应 commit: efcfcb4 → f196f5c

## 版本目标

从单用户玩具升级为具备基础安全能力的可部署系统。

## 交付内容

- **用户认证**: 手机号+密码登录, JWT Token (access + refresh)
- **Pipeline门禁校验**: 认证用户才能操作 pipeline
- **Mermaid渲染**: 流程图可视化, 动态加载减包体~800KB
- **项目管理体系重构**: 响应式UI布局, 种子数据系统完善
- **统一Coding Agent编排层**: 支持多Agent接入与全链路执行

## 关键技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 认证方式 | 手机号+密码, JWT双Token | 国内用户习惯, 无需邮箱验证 |
| Token策略 | access(30min) + refresh(7d) | 安全性和用户体验平衡 |
| Mermaid加载 | 动态import, 按需加载 | 主bundle减小800KB |

## 遗留问题

- JWT secret 有硬编码 fallback (v0.3.0 修复)
- 种子账号在生产环境也会创建 (v0.3.0 修复)
- 无API限流 (v0.3.0 修复)
- CORS生产模式默认开放localhost (v0.3.0 修复)
- SMS验证码无防暴力枚举 (v0.3.0 修复)

## 对后续版本的约束

- 所有新API路由必须挂载auth依赖
- 前端请求必须携带JWT, 通过AuthContext管理
- Token刷新逻辑在前端统一处理, 后端不做session
