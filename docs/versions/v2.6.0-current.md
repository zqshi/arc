# v2.6.0 Current — Agent Git Sync + 全量产品预览

> 状态: 进行中
> 起始日期: 2026-06-01
> 上一版本: [v2.5.0](v2.5.0-snapshot.md)

## 版本目标

1. **Agent Git Sync** — Coding Agent 完成后检测变更，用户确认后 commit/push 到远程仓库
2. **全量产品预览** — 原型预览聚合项目所有需求的页面，增量标记"新增"，提供完整产品体验

## 版本验证标准

1. Agent 编码完成后，前端弹出 diff 预览面板，用户确认后变更推送到 GitHub
2. 用户拒绝时变更保留在本地但不推送，可以后续手动处理
3. 点击"产品预览"打开包含项目所有已产出原型页面的完整应用，新增页面有"NEW"标记
4. 现有测试全部通过
5. 新增功能有对应单元测试

## 版本范围

**做什么:**
- Agent 完成后 git diff 检测 + WS 通知前端
- 前端 CodeChangesReview 组件（diff 预览 + 确认/拒绝）
- POST confirm-push 端点执行 git add/commit/push
- 项目级 prototype-bundle API 聚合全量原型
- 预览 shell 新增导航 + NEW 标记
- 项目设置中的 auto_commit 配置项

**不做什么:**
- PR 自动创建 → v2.7.0（先做直接 push 到分支）
- 冲突自动解决 → v2.7.0
- 在线原型编辑 → backlog

## 各任务实施要点

### T1 — git_sync 模块

```python
class GitSync:
    """项目目录的 git 变更检测与推送。"""
    
    async def detect_changes(self, project_path: str) -> GitChanges:
        """检测未提交的变更：git status + git diff"""
        
    async def commit_and_push(
        self, project_path: str, message: str, branch: str | None = None
    ) -> GitPushResult:
        """git add -A → commit → push，返回 commit SHA 和 remote URL"""
        
    async def get_diff_preview(self, project_path: str) -> str:
        """git diff --stat + 前 N 个文件的 patch 预览"""
```

### T2 — session_manager 集成

在 `_execute_and_poll` 的 session.complete() 后：
1. 调用 `git_sync.detect_changes(project_path)`
2. 如有变更 → 通过 WS broadcast `code_changes_ready` 事件
3. 事件包含: `{files_changed, insertions, deletions, diff_preview}`

### T3 — 前端 CodeChangesReview

- 收到 `code_changes_ready` WS 事件后弹出 diff 预览面板
- 显示: 变更文件列表 + 统计 + diff 摘要
- 用户操作: "确认推送" / "暂不推送" / "查看详情"
- 确认 → POST confirm-push → 显示推送结果

### T4 — confirm-push API

```
POST /api/todos/{todo_id}/confirm-push
Body: { message?: string, branch?: string }
Response: { commit_sha, remote_url, files_changed }
```

### T5 — auto_commit 配置

项目设置 `conversation_config.git_sync`:
```json
{
  "auto_commit": false,    // true = Agent 完成后自动 commit（不弹确认）
  "auto_push": false,      // true = commit 后自动 push
  "commit_prefix": "feat", // commit message 前缀
  "target_branch": ""      // 留空 = 当前分支
}
```

### T6 — prototype-bundle API

```
GET /api/projects/{project_id}/prototype-bundle
Response: {
  pages: [{ name, html, source_todo_id, source_todo_title, is_new }],
  navigation: { ... },
  shell_html: "..."   // 完整的可打开的 HTML
}
```

聚合逻辑:
1. 查询项目下所有 `prototype` artifact（按 todo 创建时间排序）
2. 合并 pages（同名页面以最新版本为准）
3. 标记当前请求 todo 的页面为 `is_new`
4. 生成带导航栏的 shell HTML

### T7 — 前端全量预览 shell

修改原型预览按钮:
- 调用 `api.getPrototypeBundle(projectId, todoId)` 代替单个 artifact
- 打开的 HTML 包含所有页面 + 左侧导航
- 新增页面在导航中标注"🆕"
- 导航支持页面切换

## 对后续版本的约束

- git_sync 操作必须在用户确认后执行，不可无确认静默推送（除非 auto_push=true）
- prototype-bundle 的 pages 合并以 page.name 去重，最新版本优先
- 全量预览的 shell 模板必须纯静态 HTML（不依赖外部 JS 框架），确保离线可用
