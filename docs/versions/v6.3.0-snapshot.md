## 版本目标

把 Arc 自身的迭代治理体系作为"基因"传给交付项目。新建项目时按 ProjectType 自动产出 project_charter (等价 CLAUDE.md 但按类型裁剪), 交付治理文件让交付项目的 agent 能自运转版本切换/质量检测。规范模板必须意图驱动 (非 Arc 现有规则执行式)。

## 关键决策

- **charter 与 conventions 并存分工**: charter=系统按 ProjectType 生成的意图驱动治理底座 (等价 CLAUDE.md), conventions=用户手填的项目特定补充 (保留现状零改动)。两者都注入 AI 上下文, 职责正交
- **charter 是 Project 内嵌字段非独立 Artifact 记录**: charter 是项目级元数据 (不绑定 phase/todo), 与 domain_model/context_policy 同层, 持久化为 JSONB。复用 DomainModelSnapshot/ContextPolicy 值对象模式
- **意图驱动纪律贯穿全程**: charter/CLAUDE.md 禁 Arc 规则执行式硬规则 ("文件<500行""必须auth""必修项"等), 只给目标+输出契约+上下文。复用 prompt-upgrade #8-10 范式
- **ConventionTemplateProvider 接口 + Registry 注册表**: domain 定义 abc 接口, application 实现 DefaultConventionTemplateProvider (通用骨架) + ConventionTemplateRegistry (类型特化查表+fallback)。与 v5.9.0 get_distributor/get_prototype_guide 同构, 新增 ProjectType 只在注册表填映射不加 if 分支
- **两层传递**: ① charter 文本深化把 Arc 4 样治理机制 (版本协议/上下文加载/任务依赖表/质量门禁) 意图驱动化织入通用骨架; ② GovernanceArtifactWriter 落盘交付产物 (CHARTER.md + CLAUDE.md), 传文本即传机制
- **交付产物落项目根**: CLAUDE.md 在根 + .arc/governance/CHARTER.md。CLAUDE.md 是通用 AI 入口约定, 用户确认 github 类型接受写仓库根。不预生成空 docs/versions/ 多文件 (过度设计, agent 按意图自建 .arc/versions/)
- **github 类型异步就绪处理**: local_path 初始空 (clone 前), GovernanceArtifactWriter.write() graceful skip; clone 完成后补落盘 (仿 scan 触发, try/except 非阻断)
