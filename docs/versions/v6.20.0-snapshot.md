## 版本目标

把 LLM 配置从 config.py 固定字段升级为用户级多厂商凭证管理 (DB + Fernet 加密) + 在线探活 (verify/list models) + 选用指针 (项目级覆盖)。解决现状三大缺口 (模型清单写死 / key 只判非空 / provider 硬编码两处不同步) + 安全问题 (项目级 api_key 明文存 conversation_config) + 死字段 (temperature/max_tokens 无落点)。

- **L2 infrastructure**: `llm_providers` 表 (migration z23, JSONB models + Text api_key_enc + 部分唯一索引 is_default 互斥) + `projects.llm_provider_id` FK 列 + SqlAlchemyLLMProviderRepository (ORM 赋值模式触发 onupdate, repo 不碰 crypto)。全新库 alembic check 干净。
- **L3 adapter 探活**: OpenAIAdapter.list_models (client.models.list() 免费不计费) + verify (同) / AnthropicAdapter.list_models (静态建议, 官方无 list API 诚实降级) + verify (1-token messages.create)。LLMAdapter 加 list_models/verify 非抽象方法 (不强制改 ResilientAdapter/TracingAdapter 包装器)。8 单测 mock client。
- **L4 application**: LLMProviderService (CRUD 注入式加密 + verify_credentials 临时凭证探活返 models + list_models 缓存回填 graceful) + VerifyResult (error_kind: invalid_key|http_error|network|unknown) + create is_default 互斥修复 (先 insert False 再 set_default 避免撞部分唯一索引)。16 单测 mock repo。
- **L5 链路改造**: conversation_context.get_llm_config 改读 Project.llm_provider_id → DB 凭证 (Fernet 解密) → 返回兼容 dict {provider,model,api_key,base_url}, 下游 acquire_for_project/create_llm_adapter_from_config/analysis_service 零改动; 回退旧 conversation_config["llm"] 明文 (向后兼容迁移期); Project entity + ORM + repo _to_entity/update 映射 llm_provider_id; 端点层 ProjectUpdate/ProjectResponse + apply_project_updates 显式分支 (None=取消覆盖)。
- **L6 interface**: `/api/llm` 路由 (CurrentUser 鉴权) — GET /providers/templates (真相源) + GET/POST/PATCH/DELETE /providers (分页) + POST /providers/verify + GET /providers/{id}/models (?refresh)。GET 不回 api_key 明文 (只 api_key_set, 同 settings 路由)。11 集成测 (CRUD + 互斥 + verify mock + 模板 + 分页 + 越权 404 + 项目设/取消 llm_provider_id)。
- **L7 frontend**: LLMProviderManager (列表 + 模板选择 + 验证按钮拉模型下拉 + 设默认 + 删除, 替代旧静态 MODEL_SUGGESTIONS) + SettingsPage 替换 LLMConfigSection + 删 temperature/max_tokens 死字段 + 删旧 LLMConfigSection.tsx 死代码。修 api.listTemplates 重名冲突 (→ listProviderTemplates)。tsc-b0 / vitest 97 (+6) / build0。

## 关键技术决策

| 决策 | 理由 |
|------|------|
| 凭证用户级隔离 (user_id) | 符合"我的厂商 key"语义, 为多用户留正确基础 |
| 加密复用 crypto.py Fernet (同签名凭证) | 成熟注入式模式, domain 不依赖 infrastructure (DDD 合规) |
| list_models/verify 非抽象方法 | 不强制改 ResilientAdapter/TracingAdapter 包装器, verify 流程直接用具体 adapter |
| verify 验临时凭证 (前端传未保存 key) | 不依赖保存顺序, 验"正在编辑"的凭证, 成功顺带返 models |
| Anthropic 静态建议降级 | 官方无 list API, 诚实标注不假装能力 |
| get_llm_config 返回兼容 dict (非改下游) | 单点改造, acquire_for_project/create_llm_adapter_from_config 零改动, 最小侵入 |
| 全局默认仍走 env (渐进边界) | create_llm_adapter() 同步无法 async 读 DB; 项目级 llm_provider_id 已通 DB (新链路), 全局默认保留 env fallback 向后兼容 |

## 遗留问题

- **全局默认凭证读取边界 (L5 渐进)**: `create_llm_adapter()` 同步读 config.py env, 未接 DB 默认凭证。当前: 项目级 llm_provider_id 全通 DB, 全局默认走 env fallback。完整接通全局默认走 DB 需异步化/预加载, 留 v6.21。
- per-phase/worker 选用重映射完整形态 (agent_default/worker_llm_provider 从 provider 字符串重映射到凭证 id, 保留 env 兜底), 留 v6.21。
- 多 worker 凭证缓存一致性 (Redis pub/sub), 留增强。
- Anthropic 模型清单只能静态建议 (官方无 list API, 诚实降级)。

## 对后续版本的约束

- LLM 凭证统一走 DB `llm_providers` 表 (Fernet 加密), 禁止再明文存 api_key (含 conversation_config)
- provider 列表单一真相源 = `PROVIDER_TEMPLATES` (domain), 前后端共享, 禁止前后端各自硬编码
- adapter 探活能力 (list_models/verify) 是 adapter 接口契约一部分, 新增 provider 适配器须实现
- 延续 v6.19 及之前既定约束
