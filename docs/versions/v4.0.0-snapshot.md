# v4.0.0 Snapshot — 统一执行引擎

> 状态: ✅ 已完成  
> 完成日期: 2026-06-02  
> 前置版本: [v3.10.0](v3.10.0-snapshot.md)  
> RFC: [RFC-001](../rfcs/RFC-001-unified-execution-engine.md) + [RFC-002](../rfcs/RFC-002-skill-integration-quality-plan.md)

## 版本目标

消除 Pipeline/Conversation 双架构，统一为单引擎 + 配置化约束策略。从"一个 LLM + 固定 prompt"升级为"方法论驱动 + 门禁保障 + 后验闭环"。

## 交付

### Phase 1: Pipeline 接入 ToolAwareLoop ✅
- `ConversationService` 有 project_path 时自动走 ToolAwareLoop
- 漂移检测 + 死循环检测 + 文件读写/命令执行
- Pipeline 模式也注入全阶段方法论

### Phase 2: 统一 Prompt 体系 ✅
- `PromptBuilder.build_system_prompt(phase_scope=)` 统一入口
- `ConversationService` 委托 PromptBuilder（旧方法标 deprecated）

### Phase 3: ProcessController 配置化 ✅
- `ProcessConstraint` 枚举: strict / moderate / free
- `ProcessConfig` 值对象: constraint + gate_strictness + auto_extract + show_phase_ui
- DB migration: execution_mode → process_constraint 自动迁移
- API 新增 process_constraint + process_config 字段

### Phase 4: 全阶段方法论 ✅ (v3.10.0 已完成)
- 7 个方法论模块覆盖全部阶段
- 13 条 DDD 校验规则 + 5 对交叉一致性检查
- Playwright 沙盒验证

## 关键技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| Prompt 统一方式 | phase_scope 参数化 | 最小改动，向后兼容 |
| ProcessConstraint 粒度 | 三级 (strict/moderate/free) | 比二分法更灵活，moderate 为新增的中间态 |
| 旧字段处理 | execution_mode 保留 deprecated | 前端平滑迁移，不破坏现有 API |
| 数据迁移 | migration 中自动推导 | pipeline→strict, conversation→free |

## 对后续版本的约束

- 新代码必须使用 `process_constraint` 而非 `execution_mode`
- Prompt 构建统一通过 `PromptBuilder`，不得新建私有 prompt builder
- 方法论模块只能通过 `PromptBuilder` 注入，不得在 service/route 层直接引用
