# v2.1.0 Current — DDD 工程化 + 代码质量加固

> 状态: 进行中
> 起始 commit: 37cc509 (2026-05-26)
> 上一版本: [v2.0.0](v2.0.0-snapshot.md)

## 版本目标

将 DDD 方法论从"提示词引导"升级为"LLM 驱动的全链路工程化"：三阶段自主建模（战略→事件风暴→战术）、事件风暴数据提取、LLM 驱动的领域模型质量评审。同时修复积累的 schema 漂移和代码质量问题。

## 版本验证标准

1. AI 对话产出 tech_architecture 时自主完成 DDD 三阶段建模，domain_design + event_storming 数据被正确提取
2. 领域模型 tab 点击"AI 评审"按钮，LLM 返回质量分数 + 问题列表 + 改进建议
3. 有聚合但无子域/上下文的项目，依赖关系图不再显示空白
4. `alembic check` 无 pending 变更，`ruff check` 无 F401 未使用导入

## 版本范围

**做什么:**
- DDD 三阶段自主引导 prompt（战略设计→事件风暴→战术建模）
- event_storming 数据 schema + 提取器适配
- LLM 驱动的领域模型质量校验（validate API + 前端 UI）
- 依赖关系图空状态 bug 修复
- alembic schema 对齐 migration
- ruff lint 清理 + N+1 查询优化

**不做什么:**
- 独立 DDD skill 模块或 CLI 脚本适配 → backlog
- PlantUML 生成 → 已有 SVG 依赖关系图
- 经验引擎架构重构 → backlog

## 各任务实施要点

### T2 — DDD 三阶段 prompt

- `CONVERSATION_MODE_SYSTEM_PROMPT` 阶段 5 改为"自主驱动、一次性完成"，不等用户确认
- `DDD_TDD_GUIDANCE` 增加 strategic_section / tactical_section 动态注入
- `build_ddd_tdd_section()` 从 domain_model 提取完整战略/战术上下文

### T4 — LLM 驱动领域模型校验

- 新建 `domain_model_validator.py`，复用 `create_resilient_adapter()` 模式
- 专家级 DDD 评审 prompt 覆盖战略/战术/命名/完整度四维度
- 返回 score(0-100) + level + issues[] + strengths[] + summary
- POST 端点（有 LLM 调用成本）

### T6 — alembic migration

- 只做 nullable 收紧（所有列有 server_default，安全）
- 只新增索引（重命名），不删除任何已有索引
- 自动生成的 migration 会删 HNSW 等性能关键索引，已手动修正

## 对后续版本的约束

- DDD prompt 中的 event_storming schema 已发布，后续 tech_architecture 产出物将包含 events/commands 字段
- 领域模型校验用 LLM 驱动，后续可扩展为对话式改进（用户可针对 issue 要求 AI 修正模型）
- ORM 模型仍有部分索引声明与数据库不一致（本次只做 nullable 对齐，索引保留在 DB 层），后续版本应在模型中补回 `index=True`
