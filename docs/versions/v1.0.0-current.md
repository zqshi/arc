# v1.0.0 Current — 多用户与团队

> 状态: 进行中
> 起始: 2026-05-21
> 上一版本: [v0.5.0](v0.5.0-snapshot.md)

## 版本目标

从单人工具扩展为小团队协作平台。引入角色权限、项目成员管理, 经验在团队内共享但个人经验保持私有。

## 版本验证标准

1. 3-5人团队能协作管理一个项目, 各自有独立账号和角色
2. 项目经验对团队成员可见, 个人经验仅对创建者可见
3. 管理员可邀请/移除成员, 成员只能操作自己有权限的项目

## 版本范围

**做什么:**
- 角色权限体系: admin/member/viewer (P0)
- 项目成员管理: 邀请/移除/角色变更 (P0)
- 经验访问控制: 项目经验团队可见, 个人经验私有 (P1)
- 团队经验复用: 成员间经验发现与贡献 (P1)

**不做什么:**
- 云端部署方案 → v2.0
- 定价模型 → v2.0
- 集成市场(GitHub/GitLab/CI) → v2.0
- 经验模板市场 → v2.0

## 各任务实施要点

### T1 — 角色枚举 + User model

- 新增 `UserRole` 枚举: `admin`, `member`, `viewer`
- User 表增加 `role` 列 (默认 `admin`, 保证现有用户不受影响)
- Domain entity 增加角色相关方法

### T2 — 项目成员管理

- `project_members` 表: project_id, user_id, role, invited_at, joined_at
- CRUD API: `POST /projects/{id}/members` (邀请), `DELETE /projects/{id}/members/{user_id}` (移除), `PATCH` (角色变更)
- 修改项目查询: 成员可见自己参与的项目, 不仅仅是创建的项目

### T3 — 权限中间件

- `require_role(min_role)` 依赖注入, 检查用户在项目中的角色
- viewer: 只读; member: CRUD todos/experiences; admin: 项目设置 + 成员管理
- 装饰现有路由: project settings → admin, todo CRUD → member, list/get → viewer

### T6 — 经验访问控制

- 项目经验: 项目成员均可见 (通过 project_members 关联)
- 个人经验: 仅 user_id 匹配的用户可见
- 经验搜索: 搜索范围限定为 用户个人 + 用户所属项目

## 对后续版本的约束

- 角色体系需预留扩展点 (自定义角色 → v2.0)
- project_members 表需支持团队级操作 (批量邀请等)
- 经验访问控制逻辑需与未来的 "经验模板市场" 兼容 (public scope)
