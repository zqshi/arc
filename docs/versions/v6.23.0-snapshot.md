## 关键技术决策

| 决策 | 理由 |
|------|------|
| D2 LoopConfig 迁 domain (非新建 VO) | LoopConfig 是纯 config dataclass, 属 domain 概念; 迁入消除 application 内联定义 + 与 GitSyncConfig 对称, 单一规范路径; app→domain import 合规; 4 字段 (3 持久化 + max_validation_retries 运行时默认), from_conversation_config 只读 3 持久化字段 |
| D2 默认值经 VO 实例单一源 | from_dict/from_conversation_config 通过 `LoopConfig()`/`GitSyncConfig()` 实例取默认, 消除 DEFAULT_CONVERSATION_CONFIG 与各 .get() 调用的默认值重复; drift guard 测试对齐 |
| D3 不重构 scan_manager | 核实路由 lazy import 已可 monkeypatch, current.md "需重构"判断过时; testdouble 注入即可, 零生产代码改动 |
| F1 mock 同时 patch 两工厂 | generate 走 create_llm_adapter_from_config (非 create_llm_adapter), 只 patch 后者漏前者; 两工厂返回同一 mock adapter 由 chat.return_value 统一控制 |
| F1 integration conftest 加 adapter_pool 清理 | G1A 只给 unit 加漏 integration; 模块级单例缓存跨测试残留真实 adapter, mock 工厂对已缓存 adapter 无效 → 真实 GLM → flaky+慢; mirror unit autouse 清理根治 |
| G1 B/C 选注入 adapter (C 类) | C 类 gate/validator 是纯函数无 db, 注入 adapter 保持纯函数+零 DB 耦合+最易测; B 类 template services 复制 G1 A resolve_for_context 模式无需决策 |
