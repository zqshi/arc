# v5.9.0 — 项目类型框架 + 静态站点型落地（snapshot）

> **主题**: 把"项目类型"建成 domain 一等公民 + 部署器多态框架，静态站点型端到端落地
> **状态**: ✅ 已完成（2026-06-24 归档）
> **前置**: v5.8.0
> **后续**: v5.10.0

---

## 版本目标

Arc 交付链路原为单类型硬编码（隐式假设"所有项目 = React SPA → npm run build → dist → S3"）。本版本把"项目类型"建成 domain 一等公民 + 部署器多态框架，并以静态站点型(官网)端到端落地验证框架可用。这是"支持不同项目类型落地"多版本路线的**第一步（框架地基）**。

## 验证标准达成

1. ✅ 用 Arc 创建 `project_type=static_site` 项目走完到 DEPLOYMENT 阶段，dist 上传 S3，`deploy_url` 可访问
2. ✅ `DeployService.deploy(project_type=...)` 按 type 路由（单元测试 `test_deploy_service.py` 验证选型）
3. ✅ 新增类型仅需在 `ProjectType` + `get_deployer` + `PROTOTYPE_BUILD_GUIDES` 三处注册

## 关键决策

- **ProjectType 正交维度**: 与 `backend_type`(none/supabase/embedded/external)、`app_code.framework`(react/vue) 正交，互不干扰
- **部署器多态**: `Deployer` 抽象基类 + `get_deployer` 工厂；`StaticSiteDeployer` 重构为 STATIC_SITE 实例（行为不变纯重构）；`deploy_static_site()` 改为薄封装 `deploy(project_type=STATIC_SITE,...)` 兼容现有调用点
- **prompt 参数化**: `prompts.py` 抽 `PROTOTYPE_BUILD_GUIDES: dict[str,str]`，按 `project.project_type` 注入，禁止 service/prompt 里加 `if project_type` 分支
- **DB 兼容**: `projects` 表加 `project_type` 列，`server_default='static_site'` 存量回填
