## 版本目标

修复 test_health 全量连跑时序污染(测试基础设施缺陷); 将构建产物显式建模为 BUILD artifact(BINARY_APP 构建链路锚点, 供部署门禁/签名/分发读取); 按项目类型编排流程(非app类不显示 app_code/构建产物, 复用 enabled_phases + charter 类型驱动注册表模式, 不推翻7阶段骨架); skill 多来源(inline 内联文本, 无需 SKILL.md 文件); 前端能力管理体验(CapabilityEditorModal skill 结构化 + CapabilityManager 分组 + BUILD renderer)。B(环节逻辑内容编排)分离 v6.10。

## 关键决策

- **A 按类型编排(类型级流程模板)**: 保7阶段骨架为池, 按 ProjectType 裁剪交付物显示(非完全自定义阶段)。复用 enabled_phases(预留未用)+charter 类型驱动注册表模式。DELIVERABLES_BY_TYPE: STATIC_SITE 去 app_code(无原生构建), BINARY_APP 加 build(签名/分发锚点)。PHASES_BY_TYPE 两类型都全7阶段(差异在交付物非阶段, 为后续类型裁剪预留)
- **artifact 显式建模**: BUILD artifact 仅 BINARY_APP 产出(_try_produce_build_artifact 类型守卫)。双读兼容设计 — _resolve_build_status 优先读 BUILD, fallback build_evidence/app_code/prototype/deploy_content; prototype content 仍保留 build_status(④消费改造后废弃)
- **④消费点分流核查结论**: 四消费点(build_gate/_deploy_project/_detect_sign_targets/Signer.sign)经核查已由"双读兼容 + resolve_deploy_config 类型路由(断点D) + 按后缀隐式 skip"覆盖, 无需新代码。auto_deploy 时序在 _try_produce_build_artifact 之前, _deploy_project 读 prototype content 是当前正确行为
- **C1 skill 多来源**: source=inline 直接填 content(无需 SKILL.md 文件), directory 现有。uploaded(上传文件)未实现, 前端上传组件缓做
- **D agent 显性化**: 后端复用 capability 表(type=AGENT, v6.8 W2.1 统一), /api/capabilities CRUD 已有, D 增量是前端体验(分组强化)
- **B 分离 v6.10**: 环节逻辑内容编排(methodology/prompt/gate 可编排, 流程引擎中枢重构)重量高风险, 单独版本专门设计
