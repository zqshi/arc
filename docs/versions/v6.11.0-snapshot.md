## 关键决策

### T3 错误规范化模式 (3 波 49 处)
- application 层 ValueError/HTTPException → domain/errors (AppError/NotFoundError/ConflictError), route 删 except ValueError, 全局 handler (main.py:168) 自动映射 status_code
- 语义归类: 资源不存在→NotFoundError(404), 业务约束→AppError(400), 已存在/重复→ConflictError(409)
- 状态码精确化: NotFound 500/400→404, 业务约束保持 400 (与 deployment/experience 试点一致)
- route 边界: domain 实体方法 raise ValueError 保留 route except (experience promote_to_global / project rollback_domain_model); 路由参数解析 (PhaseType/AgentType 枚举转换) 保留
- **保留 3 处系统 RuntimeError** (走全局 500 不泄露 detail): sandbox 147/160 impl not injected (防御性, 无 route catch), domain_model 151 AI 解析失败 (operations route 显式 except RuntimeError→500 保留)
- artifact confirm except (ValueError, AppError) 透传 (evaluate_sufficiency ValueError + 183 AppError 都向上)
- github clone_repo except RuntimeError→AppError (保留 except Exception 兜底, 避免 AppError 被吞→500)
- versions route 业务约束 409→400 精确化 (create_version 实体构造路径保留)

### T4 文件拆分原则
按职责拆 <500 行, 公开 API 不变 (模块级 re-export 或组合类保持符号路径可达), 优先加文件非加行。
