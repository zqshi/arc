## 设计要点

### T1: 交付物范围智能推断

**触发时机**: requirement_spec 产出后（需求澄清完成）

**推断逻辑**:
- AI 分析 requirement_spec 内容，判断需求类型
- 输出适用的交付物子集
- 更新 tracker.required（减少不适用项）

**需求类型 → 交付物映射参考**:
| 需求类型 | 跳过的交付物 |
|---------|------------|
| 纯后端/API | interaction_design, ui_spec, prototype |
| 纯前端 UI | tech_architecture (保留轻量版), deploy_report |
| 架构重构 | interaction_design, ui_spec, prototype |
| Bug 修复 | ui_spec, prototype, tech_architecture, deploy_report |
| 全栈新功能 | 无（全量） |

### T2: 工具调用历史持久化

- stream_end 时将 toolCalls 快照存入 AI message 的 metadata.tool_calls
- 前端历史消息渲染时从 metadata 读取，展示 ToolCallsCollapsed

### T3: 工具执行详情增强

- read_file: 显示文件路径 + 行数范围 + 文件大小
- write_file: 显示文件路径 + 变更行数摘要
- run_command: 显示命令 + exit code + stdout 前3行
- grep_search: 显示模式 + 匹配数量

---

## 约束

- 交付物裁剪是"建议"而非"强制" — 用户可恢复被跳过的项
- 工具 metadata 存储不超过 2KB/message（避免 DB 膨胀）
- 不改变已有 API 接口签名
