## 关键决策

### 1. APP_CODE 与 DEV_REPORT 共存不替换
- DEV_REPORT：人读文档（AI 写给人）
- APP_CODE：机器可解析工程元数据（AI 写给机器，供 DeployService/BaaS/外部 Agent 消费）

### 2. SERVICE_SPEC 作为 BaaS 锚点（不强接入）
- `data_persistence` 四值：none / embedded / external / supabase
- v5.5.0 只定义结构，`supabase` 值为"声明但拒绝执行"（application 层返回 NotImplementedError）
- v5.6.0 把 supabase 值升级为真实 provision

### 3. 字段可编辑性策略（domain/artifact/policy.py）
- 文档类 artifact：`__all__` 白名单，用户可整体编辑
- 工程产物（APP_CODE/PROTOTYPE）：空白名单，全只读（Agent 写入）
- SERVICE_SPEC：仅 `notes` 可改，结构只读

### 4. update_content 支持 partial 合并模式
- `partial=True` 时合并到原 content（仅覆盖提供字段）
- 不可编辑字段提交时抛 ValueError，含字段名

### 5. MCP deferred 决策
- Arc 已有内部 Agent 接入机制（OpenHands/Codex/Claude Code）
- MCP 主要服务外部客户端（Claude Desktop），v5.5.0 价值不足
- 移至 v5.6.0，与 BaaS 同版本推进

## 领域模型设计

### 新增值对象（domain/artifact/）
- `ArtifactType.APP_CODE` / `ArtifactType.SERVICE_SPEC`
- PHASE_ARTIFACT_MAP: DEVELOPMENT 加 APP_CODE，ARCHITECTURE 加 SERVICE_SPEC（均放在次要位，primary 不变）
- DELIVERABLE_REQUIRED_FIELDS: app_code / service_spec 必填字段
- `policy.py`: EDITABLE_FIELDS 白名单 + filter_editable_fields / is_field_editable

### APP_CODE 结构
`project_dir / tech_stack / framework / build_command / run_command / entry_points / has_backend / backend_type`

### SERVICE_SPEC 结构
`data_model_ref / data_persistence / endpoints[] / auth_strategy / external_api_base / notes`
