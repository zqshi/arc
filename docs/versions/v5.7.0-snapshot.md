## 关键决策

### 1. 模板 vs 经验
- 经验（Experience）：参考信息（弱绑定，prompt 注入），从 todo 对话提取
- 模板（DomainTemplate）：可执行骨架（强绑定，一键 apply），从 BaasSchema 泛化
- 两者平行存在，ARCHITECTURE 阶段同时检索注入

### 2. 结构泛化是纯逻辑，LLM 只做标题/分类
- extract_structure：表名→占位符（table_N），保留列类型/主键/外键结构
- LLM 仅生成标题/描述（失败 fallback 到结构化标题，不阻断）
- infer_category：关键词特征推断（ecommerce/social/workflow/saas/crud）

### 3. 衰减机制同 Experience
- confidence 按半衰期 180 天递减，长期不用变 stale
- record_usage：success +0.05 / failure -0.1
- success_rate = success_count / usage_count

### 4. 套用记录使用统计（含失败）
- apply 成功/失败都 record_usage（用于 success_rate 统计）
- 失败不吞错（重新抛出，上层决定）
- 记录使用失败仅 warning（不影响 apply 结果）

### 5. Project.user_id 补全
- v5.7.0 给 Project 实体加 user_id（创建者，本该属项目元信息）
- 用于模板提取 source_user_id 追溯

## 领域模型设计

### domain/template/
- `value_objects.py`: TemplateCategory/TemplateStatus/TemplateScope + 状态转换表
  - draft → confirmed → published → deprecated
- `entity.py`: DomainTemplate
  - confirm/publish/deprecate 状态机（draft 不可直接 publish）
  - record_usage（success/failure 调整 confidence）
  - success_rate/compute_decayed_confidence/is_stale
  - schema_template/entity_patterns/state_machine_patterns/permission_patterns
- `repository.py`: TemplateRepository Protocol（含 search_by_embedding）

### application/template/
- `extraction_service.py`: extract_structure（纯逻辑泛化）+ detect_*_patterns + infer_category + extract_template
- `matching_service.py`: search_matching（2x 过宽检索 + 阈值过滤）
- `apply_service.py`: adapt_template（LLM 适配）+ apply_template（apply + 记录使用）

### context/providers/template.py
- TemplateProvider：仅 ARCHITECTURE 阶段注入匹配模板

### interface/routes/template.py
- CRUD + 状态转换 + 语义搜索 + apply API
