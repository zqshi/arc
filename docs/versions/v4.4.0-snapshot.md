## 设计要点

### T1: AI 分析结果持久化

**存储模型**: `VersionAnalysis` 表
- `version_id` FK → Version
- `content` TEXT — markdown 分析结果
- `fingerprint` VARCHAR — 版本需求范围的哈希（todo_ids + statuses 的摘要）
- `created_at` TIMESTAMP

**缓存逻辑**:
- 计算当前版本 fingerprint = hash(sorted todo_ids + sorted statuses)
- 如果 DB 中存在相同 fingerprint 的记录 → 直接返回缓存
- 否则调用 AI 生成 → 存入 DB

**API 改造**:
- `POST /projects/{id}/versions/{vid}/analyze` → 返回 `{content, cached: bool}`
- 版本下需求变更时（创建/删除/状态变更）→ 不主动删除缓存，下次分析时 fingerprint 不匹配自然重新生成

### T3: LLM 配置

**存储**: Project.conversation_config 中新增 `llm` 字段
```json
{
  "llm": {
    "provider": "openai",       // openai | anthropic | custom
    "model": "gpt-4o",
    "api_key": "sk-...",        // 加密存储
    "base_url": "",             // 自定义端点（可选）
    "temperature": 0.7,
    "max_tokens": 16384
  }
}
```

**前端**: 设置页新增「AI 模型」区块，支持：
- Provider 下拉选择
- Model 输入/选择
- API Key 密码输入
- 高级选项（温度、max_tokens、自定义端点）

## 约束

- 分析结果缓存不设 TTL，fingerprint 变化即失效
- LLM API Key 加密存储（不可明文读取，只能覆写）
- 不影响已有 adapter_pool 架构，通过项目级配置覆盖全局默认
