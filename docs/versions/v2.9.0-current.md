## 版本目标

v2.8.0 归档后质量检测暴露了 application 层 8 条循环依赖（其中 2 条为顶层 import 高危）和 domain value_objects 测试覆盖仅 11% 的问题。本版本集中治理架构耦合，补齐测试盲区，为后续功能迭代建立干净的依赖基础。

## 版本验证标准

1. `grep -r "from arc.application" backend/src/arc/application/ | 无循环 import 路径` — 所有顶层 import 循环消除
2. domain value_objects 测试覆盖 ≥ 80%（至少 7/9 模块有测试）
3. 所有 500-800 行警告文件有明确拆分方案（已拆或记入 backlog）
4. 后端测试全量通过，无回归

## 版本范围

**做什么:**
- 消除 application 层顶层 import 循环依赖（execution↔context, execution↔orchestration）
- 消除延迟 import 循环依赖（execution↔sandbox, context↔conversation, pipeline↔artifact）
- 补齐 8 个 domain value_objects 单元测试
- 拆分至少 2 个超限文件（优先 llm_adapter.py 581行, ws/chat.py 564行）

**不做什么:**
- 新增产品功能 → v3.0.0
- 前端测试体系大补 → v3.0.0（本版本仅后端）
- Agent 适配器层测试 → v3.0.0

## 各任务实施要点

### T1 — 消除顶层 import 循环

**核心问题:**
- `execution/conversation_strategy.py:17` 顶层 `from arc.application.context.prompt_builder import ...`
- `context/prompt_builder.py:16` 顶层 `from arc.application.execution.prompts import ...`
- `orchestration/service.py:24-25` 顶层 `from arc.application.execution.tool_loop/tools import ...`
- `execution_engine.py:254` 延迟 `from arc.application.orchestration.service import ...`

**策略:** 提取共享类型/接口到 `application/shared/` 或将被双向依赖的 prompts 模块上移为独立模块，打破双向耦合。

### T2 — value_objects 测试

覆盖场景: 等值性、不可变性、边界条件、工厂方法。
目标模块: agent, artifact, orchestration, organization, pipeline, planning, project, todo, user (共 8 个缺失)。

### T3 — 延迟 import 循环

将延迟 import 改为依赖注入或事件驱动，从架构上消除耦合而非仅规避运行时错误。
