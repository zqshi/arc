# v5.4.0 — 部署层真实化（从预览到投产的地基）

> **主题**: 存储层重构 + 真实静态部署能力 + Deployment 领域建模
> **前置**: v5.3.0 完成
> **目标**: DEPLOYMENT 阶段从"空壳阶段名"变成"能把 dist/ 构建产物部署到 S3+CDN 并返回真实访问 URL"

---

## 版本目标

1. 重构 StorageAdapter：去掉 2MB 硬限、支持目录全量上传、大文件分片
2. 新建 Deployment 领域聚合（实体 + 状态机 + repository 接口）
3. 实现 S3 静态部署后端（对标 XSpace BOSDeployer，但走 DDD 分层）
4. DEPLOYMENT 阶段接入真实部署：build → upload → URL 回写
5. 预览链路兼容：原有 prototype preview 不受影响，部署与预览解耦

---

## 关键决策

### 1. 预览 vs 部署 的存储分离

| 维度 | 预览（prototype preview） | 部署（deployment） |
|------|--------------------------|-------------------|
| 触发时机 | AI 产出 prototype artifact 时 | DEPLOYMENT 阶段确认后 |
| 内容 | 单页 HTML mockup（轻量） | 完整前端工程构建产物（dist/） |
| 路径规范 | `previews/projects/{pid}/{vid}/...` | `deployments/{project_id}/{deploy_id}/` |
| 大小限制 | 2MB/文件（保持） | 无硬限（50MB 单文件上限，支持分片） |
| 访问控制 | public-read（预览用） | public-read（静态站点） |
| 生命周期 | 跟随版本，latest 可覆盖 | 不可变，每次部署独立目录 |

### 2. 部署状态机

```
pending → building → uploading → deployed → failed
                                     ↓
                                  rolled_back
```

- `building`: Agent 在沙箱内执行 `npm run build` 或等效构建
- `uploading`: 构建产物上传到 S3
- `deployed`: 上传完成，URL 已可访问
- `failed`: 构建或上传失败，记录错误原因
- `rolled_back`: 手动回滚（标记，不删文件）

### 3. CDN 与 URL 规范

```
https://{cdn_domain}/deployments/{project_id}/{deploy_id}/index.html
```

- 短期用 S3 直出（`storage_public_url` 已有）
- 中期接 CDN（配置 `cdn_domain`，S3 做 origin）
- 每次部署有独立 `deploy_id`，天然支持回滚（切 URL 即可）

### 4. 与 Agent 执行的集成点

当前 DEPLOYMENT 阶段由 Agent 执行（`execute_with_agent`），但执行后无"部署"动作。升级后：

```
Agent 执行 → 构建产物 → 调用 DeployService.deploy() → S3 上传 → URL 回写到 Version/Project
```

## 领域模型设计

### Deployment 实体

```python
# domain/deployment/entity.py

@dataclass
class Deployment:
    id: UUID
    project_id: UUID
    version_id: UUID
    todo_id: UUID | None  # 触发部署的需求（pipeline 模式）

    status: DeploymentStatus  # pending/building/uploading/deployed/failed/rolled_back
    deploy_type: DeployType  # static_site | (future: container, serverless)
    
    # 构建信息
    build_command: str  # e.g. "npm run build"
    artifact_path: str  # e.g. "dist"
    
    # 部署结果
    deploy_url: str | None
    storage_prefix: str | None  # S3 key prefix
    files_uploaded: int = 0
    error_message: str | None = None
    
    # 生命周期
    created_at: datetime
    deployed_at: datetime | None
    
    def start_build(self) -> None: ...
    def start_upload(self) -> None: ...
    def complete(self, url: str, prefix: str, file_count: int) -> None: ...
    def fail(self, reason: str) -> None: ...
    def rollback(self) -> None: ...
```

### 值对象

```python
# domain/deployment/value_objects.py

class DeploymentStatus(StrEnum):
    PENDING = "pending"
    BUILDING = "building"
    UPLOADING = "uploading"
    DEPLOYED = "deployed"
    FAILED = "failed"
    ROLLED_BACK = "rolled_back"

class DeployType(StrEnum):
    STATIC_SITE = "static_site"
    # Future: CONTAINER, SERVERLESS, BAAS_APP

class DeployConfig:
    """部署配置值对象，从项目设置或 pipeline 上下文获取。"""
    build_command: str = "npm run build"
    artifact_path: str = "dist"
    cdn_domain: str | None = None
```

### Repository 接口

```python
# domain/deployment/repository.py

class DeploymentRepository(Protocol):
    async def create(self, deployment: Deployment) -> Deployment: ...
    async def get_by_id(self, id: UUID) -> Deployment | None: ...
    async def get_latest_by_version(self, version_id: UUID) -> Deployment | None: ...
    async def list_by_project(self, project_id: UUID, ...) -> list[Deployment]: ...
    async def update(self, deployment: Deployment) -> Deployment: ...
```

## 约束与风险

- **沙箱依赖**: 构建（`npm run build`）需要在沙箱内执行。当前 sandbox_default_mode="none" 时，构建步骤由 Agent 在 local 环境完成。如 Agent 未执行构建，deploy 会失败——这是 expected behavior，DeployService 应给出明确错误。
- **不做容器部署**: 本版本只做静态站点部署。容器/Serverless 留给 v5.5.0+ BaaS 层。
- **不做 CI/CD**: 构建由 Agent 触发，不引入独立 CI runner。这是 Arc 的设计哲学——AI 执行，人审批。
