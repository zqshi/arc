## 版本目标

消除 Pipeline/Conversation 双 Prompt 体系和双执行路径，统一为单引擎 + 配置化约束策略。Phase 1 (ToolAwareLoop) 和 Phase 4 (方法论) 已在 v3.10.0 完成，本版本聚焦剩余的 Phase 2+3。

## 版本验证标准

1. `ConversationService._build_system_prompt()` 删除，统一由 `PromptBuilder` 构建
2. `ExecutionMode` 枚举废弃，被 `ProcessConstraint` 配置取代
3. 前端根据 `process_constraint` 决定展示阶梯 UI 或纯聊天 UI（同一组件）
4. 所有现有测试通过，API 响应结构不变

## 版本范围

**做什么:**
- T1: PromptBuilder 统一 — 支持 phase-scoped 和 all-deliverables 两种 scope
- T2: ConversationService 委托 PromptBuilder — 删除私有 _build_system_prompt
- T3: ProcessConstraint 值对象 — 替代 ExecutionMode 枚举
- T4: 数据库 migration — execution_mode 字段兼容
- T5: 前端适配 — ExecutionModeSection → ProcessConstraintSection

- Conversation/Pipeline 合并为单 Service → v4.1.0

## 各任务实施要点

### T1 — PromptBuilder 增加 phase_scope

当前 `PromptBuilder.build_system_prompt()` 总是注入全部未完成 deliverable。改为：

```python
async def build_system_prompt(
    self,
    conversation: Conversation,
    todo: Todo | None,
    *,
    phase_scope: PhaseType | None = None,  # 新增: None=全部, 指定=单阶段
) -> str:
```

- `phase_scope=None` → 展示全部未完成 deliverable (conversation 模式行为)
- `phase_scope=PhaseType.CLARIFICATION` → 只展示 requirement_spec 的 schema (pipeline 模式行为)

### T2 — ConversationService 委托 PromptBuilder

删除 `ConversationService._build_system_prompt()` 及其辅助方法 (约 100 行)，改为：

```python
async def _build_llm_messages(self, conversation: Conversation) -> list:
    from arc.application.context.prompt_builder import PromptBuilder
    
    builder = PromptBuilder(self.db)
    phase_type = PURPOSE_TO_PHASE.get(conversation.purpose.value)
    
    system_prompt = await builder.build_system_prompt(
        conversation, todo, phase_scope=phase_type,
    )
    ...
```

保留的私有方法：`_build_clarification_prompt` (因为有 Socratic 层级逻辑特殊性)。

### T3 — ProcessConstraint 值对象

```python
class ProcessConstraint(StrEnum):
    STRICT = "strict"       # 强制排序 + gate + 显式 confirm (= 当前 pipeline)
    MODERATE = "moderate"   # 推荐顺序 + 宽松 gate + 可跳过
    FREE = "free"           # 无 phase 概念 + 自动提取 (= 当前 conversation)

@dataclass(frozen=True)
class ProcessConfig:
    constraint: ProcessConstraint = ProcessConstraint.FREE
    gate_strictness: GateStrictness = GateStrictness.MODERATE
    auto_extract: bool = True
    require_explicit_confirm: bool = False
    enabled_deliverables: list[str] = field(default_factory=list)
```

### T4 — Migration

```sql
ALTER TABLE projects ADD COLUMN process_constraint VARCHAR(20) DEFAULT 'free';
ALTER TABLE projects ADD COLUMN process_config JSONB;
-- 数据迁移: execution_mode='pipeline' → process_constraint='strict'
-- 数据迁移: execution_mode='conversation' → process_constraint='free'
```

保留 `execution_mode` 字段 (deprecated, 只读) 直到前端完全迁移。

### T5 — 前端适配

- `ExecutionModeSection` → `ProcessConstraintSection`
- 三选一: 严格 / 适中 / 自由
- API 响应新增 `process_constraint` + `process_config` 字段
- `execution_mode` 字段保留兼容但前端不再写入

## 对后续版本的约束

- `ExecutionMode` 枚举标记 @deprecated，v4.1.0 可删除
- `process_constraint` 字段前端/后端必须同步使用
- Pipeline UI 和 Conversation UI 可根据 `constraint` 值选择展示，但底层 service 统一
