## 关键决策

### 配置文件方案 (非 DB)
内容脱离业务逻辑, git 版本控制, 随版本发布。无 DB/migration/缓存/管理界面开销。

### 载体: Python 常量模块 (非 YAML)
arc 无 pyyaml 依赖, 引入需新增依赖。prompt 大段文本用 Python 多行字符串可读性不输 YAML, 仍是 git 版本控制, 无运行时解析开销。若后续需非开发人员编辑, 再引入 YAML + 管理界面 (留 backlog)。

### 设计原则
1. **内容可编排, 管道不变**: 纯内容 (prompt 文本/字段规则/阈值/profile) 可配置; 编排逻辑 (路由/评估流程/子步骤控制) 保持代码
2. **复用 v6.9 模式**: dict + `.get(key, default)` fallback, 配置缺失回退默认
3. **一次性迁移, 无运行期双读**: 内容从代码内联迁到 content 模块, 消费方改读 content (区别于 DB 方案双读)
4. **strict 模式逻辑模块保留**: methodology strict 的 clarification_strategy/ui_design_methodology 等含路由/子步骤逻辑, 非纯内容, 保留代码

### 可配置边界
| 内容 | 可配置 (纯内容) | 保留代码 (编排逻辑) |
|------|----------------|---------------------|
| methodology | free baselines, moderate 精简 prompt, prototype_guide | strict 子模块 (clarification_strategy 路由, *_methodology 子步骤) |
| prompt | PHASE_SYSTEM/EXTRACTION_PROMPTS, _PHASE_INFERENCE_PROMPT | prompt_builder 组装逻辑 |
| gate | DELIVERABLE_REQUIRED_FIELDS, GateProfile 阈值, GATE_EVALUATION_PROMPT | 4 层评估流程 (结构→方法论→一致性→LLM) |

### 内容迁移纪律
逐字核对 (prompt 文本影响 LLM 输出), 不得改写措辞 — 只改读取来源。每步 red-green-refactor: 现有测试作回归保护 → 迁移 → 再跑回归。
