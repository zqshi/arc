# v5.5.0 — DEVELOPMENT 产物补全 + 编辑能力暴露（从文档到工程）

> **主题**: 把 DEV_REPORT 文档升级为"文档 + APP_CODE 工程产物 + SERVICE_SPEC 服务契约"，暴露 updateArtifact UI / rollback 入口，引入 MCP server 锚点
> **前置**: v5.4.0 完成（部署地基就绪）
> **核心价值**: 解决"AI 生成的应用只有文档没有可追踪代码工程"的根本断层，为 v5.6.0 BaaS 接入准备锚点

---

## 版本目标

1. **APP_CODE artifact**：把 DEVELOPMENT 阶段从"只有 DEV_REPORT 文档"升级为"文档 + 可追踪代码工程元数据"
2. **SERVICE_SPEC artifact**：ARCHITECTURE 阶段产出服务契约，作为 v5.6.0 BaaS 接入的结构化锚点（data_persistence 字段预留）
3. **updateArtifact UI 暴露**：前端组件让用户能查看/编辑 artifact 内容，激活已有但沉睡的 API
4. **rollback 入口显式化**：DeployReport 加"回滚部署"按钮，ProjectDetail 提升版本回滚可见性
5. **MCP server 骨架**：Arc 作为 MCP server 暴露 artifact 服务，为"外部 Agent 接入"打基础（不引入 MCP 客户端）

---

## 关键决策

### 1. APP_CODE 与 DEV_REPORT 共存，不替换

| 维度 | DEV_REPORT（保留） | APP_CODE（新增） |
|------|--------------------|------------------|
| 定位 | 人读文档 | 机器可解析的工程元数据 |
| 内容 | test_design / implementation / validation（自然语言） | project_dir / build_command / run_command / tech_stack / entry_points |
| 消费者 | 用户阅读、经验提取 | DeployService、未来 BaaS provision、MCP 外部 Agent |

**为什么不替换**：DEV_REPORT 是"AI 写给人的开发总结"，APP_CODE 是"AI 写给机器的工程清单"。两者用途不同，共存的成本只是多一个 artifact 类型。

### 2. SERVICE_SPEC 作为 BaaS 锚点（不强接入）

SERVICE_SPEC 的 `data_persistence` 字段定义四种值：
- `none` — 纯前端，无后端（当前大多数 prototype 的现状）
- `embedded` — 前端嵌入式存储（localStorage / IndexedDB / SQLite WASM）
- `external` — 对接已有后端（用户提供的 API base URL）
- `supabase` — 走 Arc 平台 BaaS（v5.6.0 实现）

**v5.5.0 只定义结构**，所有 SERVICE_SPEC 都标记为 `none` 或 `embedded`。`supabase` 值在 v5.5.0 是"声明但拒绝执行"状态，由 application 层返回明确错误。

### 3. updateArtifact UI 暴露范围

**v5.5.0 暴露**：
- artifact 内容的 JSON 查看器（read-only 切到 edit 模式）
- 编辑后保存调 updateArtifact API
- 限制：只允许编辑 `extra` / 文档类字段；`project_dir` / `build_status` 等工程字段由 Agent 写入，UI 只读

**不暴露**：
- 创建新 artifact（仍由 Agent 在 pipeline 阶段产出，用户不手动创建）
- 删除 artifact（破坏审计链）

### 4. rollback 入口的两种语义

| 入口 | 当前状态 | v5.5.0 升级 |
|------|---------|-------------|
| **部署回滚**（Deployment.rollback）| API 存在，UI 无入口 | DeployReport 卡片加"回滚到此部署"按钮 |
| **领域模型回滚**（DomainModel.rollback）| API 存在，入口在 ModelHistoryPanel 隐蔽 | ProjectDetail DomainModelTab 加显式"历史版本"入口 |
| **版本回滚**（ProjectVersion.rollback） | 不存在 | 本版本不做，记入 v5.6.0 评估 |

### 5. MCP server 最小可用

Arc 作为 MCP server 暴露以下 tool（给外部 Agent 用）：
- `arc.get_artifact(artifact_id)` — 读取 artifact 内容
- `arc.list_artifacts(project_id, phase?)` — 列出项目的 artifact
- `arc.update_artifact(artifact_id, content)` — 更新 artifact（走和 UI 一样的 service）

**不做**：
- MCP 客户端（Arc 调用外部 MCP server）—— 留给 v5.6.0+
- Agent 通过 MCP 调用 Arc（循环依赖风险）

## 领域模型设计

### APP_CODE 值对象

```python
# domain/artifact/value_objects.py (扩展)

@dataclass(frozen=True)
class AppCodeArtifact:
    """AI 生成的代码工程元数据（机器可解析）。"""
    project_dir: str           # 相对路径，e.g. "generated/my-app"
    tech_stack: list[str]      # ["react", "typescript", "vite"]
    build_command: str         # "npm run build"
    run_command: str           # "npm run dev"
    entry_points: list[str]    # ["src/main.tsx"]
    framework: str             # "react" | "vue" | "svelte" | "vanilla"
    has_backend: bool = False  # 是否包含后端代码（v5.5.0 通常 False）
    backend_type: str | None = None  # "none" | "embedded" | "external" | "supabase"
```

### SERVICE_SPEC 值对象

```python
@dataclass(frozen=True)
class ServiceSpecArtifact:
    """服务契约定义 — v5.6.0 BaaS 接入的结构化锚点。"""
    data_model_ref: str         # 引用 DomainModelSnapshot.version
    data_persistence: str       # "none" | "embedded" | "external" | "supabase"
    endpoints: list[EndpointSpec]  # API 端点定义
    auth_strategy: str          # "none" | "jwt" | "supabase_auth" | "external"
    external_api_base: str | None = None  # data_persistence="external" 时填写
    notes: str | None = None    # 自由文本备注

@dataclass(frozen=True)
class EndpointSpec:
    method: str                 # GET/POST/PUT/DELETE
    path: str                   # "/api/users"
    description: str
    auth_required: bool = True
```

## 约束与风险

- **APP_CODE.project_dir 真实性**：Agent 可能产出与实际工程目录不符的 project_dir。本版本不做验证（信任 Agent），v5.6.0 评估是否加路径校验
- **SERVICE_SPEC.data_persistence="supabase" 在 v5.5.0 是死值**：声明后 application 层返回 NotImplementedError，避免误导用户以为已有 BaaS 能力
- **MCP server 协议选择**：优先按 MCP 官方 Python SDK（modelcontextprotocol/python-sdk）实现；若 SDK 不稳定则降级为简单 JSON-RPC
- **updateArtifact 并发**：多端同时编辑同一 artifact 的冲突处理——本版本用乐观锁（updated_at 对比），冲突时返回 409
- **不在 v5.5.0 做**：BaaS 真实接入（v5.6.0）、版本回滚（v5.6.0 评估）、MCP 客户端（v5.6.0+）
