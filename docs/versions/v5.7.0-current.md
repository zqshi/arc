# v5.7.0 — 领域模型模板沉淀（经验引擎核心壁垒）

> **主题**: 从已交付项目提取可复用的领域模型模板，新项目冷启动时语义匹配推荐
> **前置**: v5.6.0 完成（BaaS 层能跑真实应用，领域模型可执行化）
> **核心价值**: Arc 产品愿景"越用越聪明"的具象化落地——用得越多，模板越丰富，新项目越快

---

## 版本目标

1. 定义"领域模型模板"领域概念：从具体项目的 BaasSchema 中抽象出可复用模板
2. 实现自动提取：项目版本 release 时，自动从 BaasSchema + _meta_* 提取模板草稿
3. 实现语义匹配：新项目创建需求时，embedding 搜索匹配历史模板并推荐
4. 实现模板套用：选中模板后一键 apply 到新项目的 Supabase schema
5. 模板生命周期：draft → confirmed → published（个人/组织可见）→ deprecated

---

## 关键决策

### 1. 模板 = 领域模型的"经验"

类比 Arc 现有经验系统：

| 维度 | 经验（Experience） | 领域模型模板（DomainTemplate） |
|------|------------------|------------------------------|
| 来源 | 从 todo 对话中 LLM 提取 | 从已部署项目的 BaasSchema 中 LLM 泛化 |
| 粒度 | 一个技术决策/踩坑 | 一套实体+状态机+权限+Action 的完整骨架 |
| 复用方式 | 注入 prompt 上下文（参考信息） | **一键 apply 到 Supabase**（可执行） |
| 适配方式 | 人读了参考就好 | LLM 根据新需求裁剪/扩展模板后 apply |
| scope | 个人/项目 | 个人/组织/公开市场（远期） |

**核心差异**：经验是"参考信息"（弱绑定），模板是"可执行骨架"（强绑定）。模板被套用后直接生成真实数据库结构。

### 2. 模板提取逻辑

```
项目 Version release
  → 读取 BaasSchema (tables + policies + transitions + actions)
  → LLM 泛化 prompt:
      "将以下具体的领域模型抽象为可复用模板：
       - 去掉项目特定的表名/字段名，保留结构模式
       - 识别核心实体模式（如：用户-内容-评论、订单-商品-支付）
       - 保留状态机跃迁逻辑（不要具体状态名，保留模式）
       - 保留 RLS 权限模式（owner-based, role-based, team-based）
       - 输出：模板名、适用场景、实体清单、状态机模式、权限模式"
  → 生成 DomainTemplate (draft)
  → 人工审核确认
```

### 3. 模板套用流程

```
新项目 ARCHITECTURE 阶段
  → ExperienceService.search_similar(需求描述) 匹配经验
  → DomainTemplateService.search_matching(需求描述) 匹配模板
  → 推荐列表展示给用户（经验 + 模板）
  
用户选中模板
  → LLM 适配 prompt:
      "基于以下模板和新项目需求，生成具体的领域模型：
       - 模板: {template_schema}
       - 需求: {requirement}
       - 项目技术栈: {tech_stack}
       输出完整的 BaasSchema JSON"
  → 生成适配后的 BaasSchema
  → 用户确认 → BaasService.apply_model()
```

### 4. 模板分类体系

| 类型 | 示例 | 核心模式 |
|------|------|---------|
| CRUD App | 博客、CMS、知识库 | User-Content-Category, 无状态机 |
| 工作流 App | 审批、工单、任务管理 | Entity 有状态机, Role-based 权限 |
| 电商 | 商城、预约系统 | Order 状态机, 库存扣减 Action, 支付回调 |
| 社交 | 社区、评论系统 | Follow/Like 关系表, 内容审核状态机 |
| SaaS 后台 | 多租户管理平台 | Team-based 权限, Org→Member→Resource |

### 5. 与现有 ExperienceService 的关系

**不合并，平行存在**：

- `ExperienceService` → 沉淀"技术决策/踩坑"（文本级知识）
- `DomainTemplateService` → 沉淀"应用骨架"（结构化模型）
- 两者在 ARCHITECTURE/DEVELOPMENT 阶段**同时被检索**，一起注入上下文
- 远期统一为"经验引擎"的两个维度，但 v5.6.0 保持独立模块清晰度

## 领域模型设计

### DomainTemplate 实体

```python
# domain/template/entity.py

@dataclass
class DomainTemplate:
    id: UUID
    
    # 元信息
    title: str  # "SaaS 多租户后台模板"
    description: str  # 适用场景描述
    category: TemplateCategory  # crud_app/workflow/ecommerce/social/saas
    
    # 来源追溯
    source_project_id: UUID | None  # 提取自哪个项目
    source_version_id: UUID | None
    source_user_id: UUID
    
    # 核心内容：泛化后的 BaasSchema
    schema_template: dict  # 与 BaasSchema 同构，但字段名是占位符
    entity_patterns: list[str]  # ["User-Content-Category", "Owner-Resource"]
    state_machine_patterns: list[str]  # ["draft→review→published→archived"]
    permission_patterns: list[str]  # ["owner-based", "role-based"]
    
    # 搜索
    tags: list[str]
    embedding: list[float] | None  # 语义向量
    
    # 生命周期
    status: TemplateStatus  # draft/confirmed/published/deprecated
    scope: TemplateScope  # personal/organization/public
    
    # 统计
    usage_count: int = 0
    success_rate: float = 0.0  # 套用后项目成功部署的比例
    
    # 衰减（同 Experience）
    confidence: float = 0.8
    created_at: datetime
    last_used_at: datetime | None
    
    def confirm(self) -> None: ...
    def publish(self) -> None: ...
    def deprecate(self) -> None: ...
    def record_usage(self, success: bool) -> None: ...
```

### 统一搜索接口

```python
# application/knowledge/unified_search.py (新增)

class UnifiedKnowledgeService:
    """统一检索经验 + 模板，按 relevance 混排返回。"""
    
    async def search(
        self, query: str, *, project_id=None, user_id=None, limit=10
    ) -> list[KnowledgeItem]:
        # 并发搜索两个维度
        experiences = await self.exp_service.search_similar(query, ...)
        templates = await self.template_service.search_matching(query, ...)
        # 按 embedding distance 混排
        return merge_and_rank(experiences, templates, limit)
```

## 验收标准

1. ✅ 已部署项目 release 版本时，自动生成领域模型模板草稿
2. ✅ 新项目 ARCHITECTURE 阶段，能搜索到语义相关的模板并展示
3. ✅ 选中模板后，LLM 适配生成具体 BaasSchema，用户确认后一键 apply
4. ✅ 模板 usage_count 正确追踪，支持按使用频率排序
5. ✅ 模板 scope 隔离正确：personal 只自己可见，organization 团队可见
6. ✅ 衰减机制：长期未使用的模板 confidence 下降

## 远期演化（不在 v5.6.0 范围，记录方向）

- **模板市场**: scope=public 的模板可分享给其他 Arc 用户（类似 XSpace Skill 市场）
- **模板组合**: 多个小模板组合成大模板（如 "Auth模板 + CRUD模板 + 支付模板"）
- **模板版本化**: 模板自身有版本演进，依赖它的项目可选择升级
- **行业模板包**: 针对特定行业预设的模板集合（SaaS/电商/教育/医疗）
- **社区贡献**: 开源模板 + 评分机制

---

## 约束与风险

- **冷启动**: v5.6.0 上线时可能只有 1-2 个项目完成了 BaaS 部署，模板库极小。缓解：预置 3-5 个通用模板（CRUD/Workflow/SaaS）作为种子数据。
- **泛化质量**: LLM 泛化可能过度抽象导致模板套用后不好用。缓解：保留 source_project_id 追溯，用户反馈"不好用"时降低 confidence。
- **BaasSchema 演进兼容**: 模板基于 v5.5.0 的 BaasSchema 结构。如果 v5.7+ 改了 schema 格式，旧模板需要迁移。缓解：模板内嵌 schema_version 字段。
