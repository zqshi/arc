## 版本目标

当前 AI 对话模式是纯文本聊天框，没有代码操作能力 — 不能读文件、不能执行命令、不能 clone 仓库。Agent 被设计为"有脑子有手脚有记忆的虚拟队友"，但实际只有嘴。本版本的核心目标是让 Agent 真正能操作代码：给对话模式装备 shell 工具、文件读写能力、自动代码仓库关联，使其能独立完成代码分析和开发任务。

同时修复已发现的交互问题（配额、GitHub 连接流程）和架构债务中最关键的 Route 层逻辑泄漏。

## 版本验证标准

1. 对话模式下 AI 能自主读取项目 local_path 下的文件、列目录、grep 搜索
2. 对话模式下 AI 能执行 shell 命令（git clone、npm install、测试等）
3. 连接 GitHub 后自动 clone 到 local_path（如未配置则自动选择路径）
4. AI 对话开始时自动感知项目代码上下文（codebase_summary + 按需读文件）
5. 已有功能不回归：所有现有测试通过

## 各任务实施要点

### T1 — 对话模式 Tool Use 基础设施

**目标**: 让 ConversationExecutionService 的 LLM 调用支持 tool_use，AI 能发起工具调用并获得结果。

**方案**:
1. 创建 `execution/tools.py` — 定义工具注册表 (ToolRegistry)
2. 修改 `agent_loop.py` 的 `run()` — 识别 tool_use 事件，调用工具，将结果作为 tool_result 喂回 LLM
3. 修改 `ai/llm_adapter.py` — LLM 请求中携带 tools 参数（Claude API 的 tool_use / OpenAI 的 function_calling）

**工具定义格式**:
```python
@dataclass
class ToolDefinition:
    name: str
    description: str
    input_schema: dict  # JSON Schema
    handler: Callable[[dict], Awaitable[str]]  # 执行函数

class ToolRegistry:
    tools: list[ToolDefinition]
    
    async def execute(self, name: str, input: dict) -> str: ...
    def to_api_format(self) -> list[dict]: ...  # 转为 LLM API 格式
```

**关键决策**:
- 工具结果直接插入 LLM messages 作为 tool_result，不暴露给用户（除非是最终输出）
- 工具调用过程以 SSE 事件 `tool_call` 推送给前端，前端显示为"正在读取文件..."类的状态

### T2 — Shell 执行工具

**工具定义**:
```python
Tool(
    name="run_command",
    description="在项目工作目录下执行 shell 命令。用于 git、npm、pytest 等操作。",
    input_schema={"command": "string", "timeout": "integer (optional, default 30)"}
)
```

**安全约束**:
- 工作目录锁定为 `project.local_path`，不允许 cd 到其他位置
- 命令超时默认 30s，最大 120s
- 危险命令黑名单：`rm -rf /`、`mkfs`、`dd` 等
- 输出截断：stdout/stderr 各最多 10000 字符

### T3 — 文件读写 + 目录 + Grep

**工具集**:
```python
tools = [
    Tool("read_file", "读取文件内容", {"path": "string", "start_line": "int?", "end_line": "int?"}),
    Tool("write_file", "写入或创建文件", {"path": "string", "content": "string"}),
    Tool("list_directory", "列出目录内容", {"path": "string", "recursive": "bool?", "max_depth": "int?"}),
    Tool("grep_search", "在项目中搜索文本", {"pattern": "string", "path": "string?", "include": "string?"}),
]
```

**安全约束**:
- 所有路径必须在 `project.local_path` 之下（路径遍历防护）
- read_file 单次最多 500 行（超出需分段读取）
- list_directory 默认 max_depth=2
- grep 结果最多 50 条匹配

### T4 — System Prompt 代码操作指引

在 `context/provider.py` 的 `to_agent_section()` 中注入：

```
## 代码操作能力
你可以直接操作项目代码。项目工作目录: {local_path}
- 使用 list_directory 了解项目结构
- 使用 read_file 阅读源码
- 使用 grep_search 搜索代码
- 使用 run_command 执行命令（git/npm/pytest等）
- 使用 write_file 修改代码

在开始分析需求时，先用 list_directory 了解项目结构，再针对性读取关键文件。
不要让用户手动提供代码内容 — 自己去读。
```

### T5 — GitHub 连接自动 clone + scan

**流程**:
1. `connect_github` 成功后
2. 如果 `project.local_path` 为空 → 自动选择 `~/.arc/repos/{owner}/{repo}` 作为 clone 目标
3. 执行 `git clone {repo_url} {local_path}` （如果目录已存在则 `git pull`）
4. 自动触发 `scan_manager.start_scan()`
5. 返回结果中包含 `local_path` 和 scan 状态

### T6 — Agent 执行结果回写对话

- 前端以折叠块展示工具调用过程
