# v6.12.0 Current — 容器构建链路扩展（web + android capacitor 镜像）

> 状态: 进行中 (v6.10 归档后激活)
> 起始 commit: 71f38ac (2026-06-28)
> 上一版本: [v6.10.0](v6.10.0-snapshot.md)

## 版本目标

v6.0 容器化构建 runtime 只跑通波次1 (tauri linux), web/android 两条构建链路以"预留注释"形态搁置 — BuildTarget 枚举 2 个值、DEFAULT_BUILD_IMAGES、DeployConfig.for_type、Makefile、configmap 全部留了激活点但未接通。本版本目标: 激活 v6.0 波次2/3 预留点, 打通 web 资源构建与 android capacitor apk 构建两条容器链路, 使 BINARY_APP 项目类型覆盖全平台构建分发, 不动 v6.0 已一次做对的架构层。

## 版本验证标准

1. `arc/web-builder` 镜像: 容器内 `npm run build` 产 dist, BuildTarget.WEB 注册可达
2. `arc/android-builder` 镜像: 容器内 `npx cap build android` 产 apk, BuildTarget.CAPACITOR_APK 注册可达 (CI 标 slow skip, 本地手动验证)
3. 前端构建目标选择器放开 WEB/CAPACITOR_APK, tsc-b 0 / vitest 全绿
4. 质量检测协议 6.1-6.7 必修项通过

## 版本范围

**做什么:**
- 波次2 web-builder: 激活 BuildTarget.WEB + 新建 web-builder.Dockerfile + 注册镜像 + DeployConfig.for_type WEB 分支 + smoke
- 波次3 android-builder: 激活 BuildTarget.CAPACITOR_APK + 新建 android-builder.Dockerfile (JDK17+SDK+NDK) + 注册镜像 + for_type CAPACITOR_APK 分支 + apk smoke (slow)
- 前端构建目标选择器放开 + ArtifactType 类型补全

**不做什么:**
- 不改 v6.0 架构层 (BuildTarget 维度/二维镜像推导/policy_resolver/runtime 零改) — 预留点已就位, 只填注册表
- 不做真实产物签名验证 (v6.1 遗留, 待构建链路全通后) → 留 backlog
- 不做商店分发 (v6.2 已覆盖, 本版本仅构建产 apk)

## 各任务实施要点

### T1 — 波次2 web-builder

**6 处预留激活点** (v6.0 已留好, 逐字对照 v6.0 注释):
1. `domain/sandbox/value_objects.py:34` — 取消注释 `WEB = "web"`, 改 docstring 标注波次2 已激活
2. `domain/sandbox/build_images.py:23` — DEFAULT_BUILD_IMAGES 加 `(ProjectType.BINARY_APP, BuildTarget.WEB): "arc/web-builder:latest"`
   - ⚠️ 设计确认: WEB target 绑 BINARY_APP 还是 STATIC_SITE? v6.0 注释写两者都加, 但 STATIC_SITE 本身 for_type 已走 npm run build+dist (不需 WEB target)。**T1 开工先确认**: WEB target 语义 = "BINARY_APP 项目的 web 资源构建" (capacitor 打包前置), 还是 "STATIC_SITE 也走容器构建"。倾向前者 (后者与 STATIC_SITE 现状重复, v6.0 snapshot 已点明此矛盾)。
3. `domain/deployment/value_objects.py:72` — for_type BINARY_APP 分支加 `if target == WEB: return DeployConfig(build_command="npm run build", artifact_path="dist")`
4. `infrastructure/sandbox/images/web-builder.Dockerfile` — 新建 (参考 tauri-builder.Dockerfile 结构: node + 构建工具链, 无需 webkit2gtk)
5. `infrastructure/sandbox/images/Makefile:15-16` — 取消 web-builder 注释, 加 .PHONY
6. `k8s/configmap.yml:40` — ARC_SANDBOX_BUILDER_IMAGES 注释示例已是 `{"web":"arc/web-builder:latest"}`, 确认对齐

**smoke 验证**: `make web-builder` 建镜像 → 容器内 `npm run build` 产 dist (用一个最小 vite 模板)
**测试**: DEFAULT_BUILD_IMAGES 注册单元测试 + resolve_build_image(BINARY_APP, WEB) 返回 web-builder; for_type WEB 分支测试

### T2 — 波次3 android-builder

**镜像是大头** (JDK17 + Android SDK + NDK, 2-3GB):
- Dockerfile 要处理 SDK licenses 自动接受 (`android-sdk-license` 预写 yes) + NDK 版本固定 (capacitor 推荐 NDK r25c)
- capacitor-cli 全局安装 + gradle
- 镜像构建慢 (CI 默认 skip, 本地 `make android-builder` ~10-20min)
- 参考 v6.0 tauri-builder 的 licenses 处理模式

**激活点同 T1 结构**:
1. `value_objects.py:35` — 取消注释 `CAPACITOR_APK = "capacitor_apk"`
2. `build_images.py` — 加 `(ProjectType.BINARY_APP, BuildTarget.CAPACITOR_APK): "arc/android-builder:linux"`
3. `deployment/value_objects.py:73` — for_type CAPACITOR_APK 分支: `npx cap build android` → `android/app/build/outputs/apk`
4. `android-builder.Dockerfile` 新建
5. Makefile 取消注释
6. configmap 对齐

**capacitor 构建链**: `npm run build` (web dist) → `npx cap copy` (拷贝到 native) → `npx cap build android` (apk)。build_command 需组合 (确认是否用 shell 脚本封装多步, 或 DeployConfig 支持多命令 — T2 设计项)
**smoke**: 标 `@pytest.mark.slow`, CI skip; 本地 `make android-builder` 后跑最小 capacitor 模板产 apk
**测试**: 注册 + for_type CAPACITOR_APK 分支单元测试 (镜像 smoke 走 slow 集成测试)

## 风险

- **android 镜像构建复杂度**: NDK 版本/capacitor 兼容/licenses 接受, 调试可能跨多会话。缓解: 镜像 smoke 标 slow, CI 不阻断; 先把注册+for_type+测试做对, 镜像验证可本地手动
- **WEB target ProjectType 绑定歧义**: v6.0 注释同时写了 BINARY_APP 和 STATIC_SITE, 需 T1 开工先定 (倾向 BINARY_APP, 避免 STATIC_SITE 重复)
- **capacitor 多步 build_command**: npm build + cap copy + cap build, DeployConfig 单 build_command 字段可能不够, T2 需评估是否引入构建脚本封装

## 约束

- 不动 v6.0 架构层 (BuildTarget 维度/二维镜像推导/runtime 零改), 只填 v6.0 预留注册点
- 镜像 Dockerfile 入 infrastructure/sandbox/images/, 跟 tauri-builder 同目录同 Makefile 模式
- 镜像构建 smoke 标 slow, CI 默认 skip (镜像 2-3GB 不进 CI)
- 延续 v6.9/v6.10/v6.11 约束
- 前端 tsc 检查用 `tsc -b --noEmit` 或 `npm run build`
- 新会话开始: 读本文件 + 执行会话级巡检 (DDD 层级/循环依赖/文件超限)
