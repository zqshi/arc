## 版本目标

建立领域模型变更基础设施：版本化快照、评审反馈实体化、闭环流程。

## 交付物

1. **快照机制**: `Project.upgrade_domain_model()` 变更前自动创建快照，`rollback_domain_model()` 支持按版本回滚
2. **ReviewFeedback 领域模块**: 实体 + 值对象 + 仓储接口 + ORM + repository 实现
3. **变更分级器**: 确定性规则引擎，category × severity → additive/structural/breaking
4. **ReviewService 闭环**: Validator 产出自动持久化为 ReviewFeedback
5. **API 端点**: review-feedbacks CRUD + domain-model/history + rollback
6. **DomainModelExtractor 改造**: 改用 `upgrade_domain_model()` 路径，所有变更自动产生快照
7. **+63 tests** (894 total)

## 关键决策

| 决策 | 选项 | 理由 |
|------|------|------|
| 快照存储 | JSONB 数组 vs 独立表 | 前期变更频率低（每项目几十次），JSONB 简洁无需 JOIN |
| 分级方式 | 规则引擎 vs LLM | 确定性优先，12 条规则覆盖全矩阵，零延迟零成本 |
| ReviewFeedback 位置 | 扩展 project 模块 vs 独立 review 模块 | 独立模块：职责清晰，不膨胀 project 聚合 |
| Validator 改造 | 改签名 vs 上层包装 | 上层 ReviewService 包装，不改原始 validate_domain_model() |
