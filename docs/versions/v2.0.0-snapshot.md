# v2.0.0 Snapshot — 商业化基础设施

> 状态: 已完成
> 上一版本: [v1.2.0](v1.2.0-snapshot.md)

## 版本目标

让产品从"本地工具"进化为"可售卖的 SaaS 产品"：多租户隔离、三级定价、GitHub 集成、云端部署。

## 交付物

| 任务 | 交付 |
|------|------|
| T1: project.py 路由拆分 | `interface/routes/project/` 8 文件, 每文件 ≤300 行 |
| T2: 多租户隔离 | Organization domain + membership + org-scoped 查询, migration `z1_multi_tenant` |
| T3: 定价模型 | Free/Pro/Team 三级, QuotaService + UsageDaily, 前端 403 拦截 + 用量展示, migration `z2_usage_daily` |
| T4: 云端部署 | `docker-compose.prod.yml`, `k8s/` (6 manifests), `docker-publish.yml` CI/CD, nginx 反代+gzip+WS |
| T5: GitHub 集成 | GitHubClient + GitHubService, Webhook 路由 (HMAC-SHA256), Issue↔Todo 双向同步, 前端连接 UI, migration `z3_github_integration` |

## 关键决策

1. **多租户方案**: 共享库 + org_id 列过滤（非独立 schema），简单够用，未来可升级
2. **定价执行**: 后端 QuotaService 校验 → 前端 quotaEvents 事件总线 → Toast 提示，WebSocket 也走 quota_exceeded 事件
3. **GitHub 认证**: Project 级 PAT（非 OAuth App），MVP 够用
4. **K8s 策略**: 纯 YAML manifests（非 Helm），外部托管 PG，Ingress 路径路由
5. **前端构建**: nginx 反代统一入口（API/WS/静态），生产环境 VITE_API_URL="" 走相对路径

## 对后续版本的约束

- 多租户 org_id 过滤模式已全局注入，后续查询必须延续
- 定价模型确定后 rate limiting middleware 全局生效
- GitHub webhook 签名验证模式为后续集成标准
- K8s manifests 中 image 引用需替换为实际 GHCR 地址
